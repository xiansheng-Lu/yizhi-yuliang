## 三条DoD与实现

1. Python声明表与0024只读状态表一致：14生命周期事件、19条合法边，前端保持十二态。180项纯规则用例逐一覆盖19合法边、149非法组合、两类UNKNOWN及缺风险/旧检查/旧策略/自审批/E0伪匹配/现值变化/资金增额/过期重试/失败检查覆盖等反例。非法动作409，旧版本409，状态归约不能通过客户端字符串指定目的状态。
2. 受控数据库函数重新检查当前身份、成员/租户/用户状态、动作权限与店铺/账户范围。审批读取只为具有task.approve与双范围的非申请人精确开放该任务，不提供通用跨私有RLS查询。按status+version做条件更新；取消、过期、领取共享claimed_at为空且dispatch_started_at为空谓词，确认/批准/领取/重试在最终SQL再次检查有效期。真实PG并发测试覆盖到期与未到期两种三方竞争，仅一方修改版本/事件/同事务探针。终态无普通自动出口。
3. FAILED只有显式SAFE_RETRY边。重新复核风险/策略/白名单/当前值/E1依据，资金增加默认拒绝，沿用原申请并保留失败事件；当前源码不创建真实执行attempt，M2-13/18的实际参与者尚未装配。提交未知保持EXECUTING、accepted=null、verification=UNKNOWN、RESULT_UNKNOWN且retryable=false；已受理回读未知保持VERIFYING与accepted=true，均不重发或计成功。E0不能被当成E1/E2；MISMATCH不等于资金可释放，参与者必须按R00-03证据等级处理。

状态、document、版本化job_events、参与者数据库副作用和审计同事务，任一失败全回滚。数据库拒绝直接UPDATE状态/规则/历史，普通运行角色也不能直接INSERT终态或不完整任务；转移函数不能改目标/载荷/原键等不可变字段，不能改写history前缀。新状态与审批事实在CommandJob模型再次核对。
