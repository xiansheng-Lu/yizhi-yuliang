## 三条DoD与实现

1. Redis TIME与Lua在应用/账户两层原子准入，429按Retry-After冻结范围；无明确范围时保守冻结两层。缺失等待至少1秒，不可确认等待转人工持有，不用循环猜测。受控客户端每次最多一个HTTP尝试，原出站键查档不扣配额、不重复发送或报告。新键拒绝发生在PG请求/审计写入和HTTP之前。`reschedule_connector_task`真实更新持有效租约的connector.*调度单为RESCHEDULED，保留尝试次数并释放租约；超最大次数或人工持有转FAILED，不能改写命令执行单状态。重新领取/增加次数由后续同步调度接入。
2. 连续上游失败打开熔断，OPEN不出站；超期仍须只读PROBE，HALF_OPEN仅一个带租期的探测。epoch与探测令牌拒绝旧探测关闭新状态；单次结果报告去重48小时。业务确认成功才关闭探测，200无业务证据不能恢复。状态可检查，手工解除须证据引用，解除后仍须探测。Redis不可用禁止新请求，已保存PG结果不被后续Redis报告故障改写。
3. SYNC不能消耗EXECUTE/READBACK保留额度；应用配额跨同应用账户共享，账户拒绝不误扣应用桶。重复429/熔断按应用/账户冷却去重告警；通知通道故障不改变已落状态。未配置真实通知发送器，本轮无对外消息。

命令、数量、环境见[verification.json](verification.json)。本卡用真实Redis执行Lua/并发/配额/状态/告警去重，用真实PG普通角色验证延期及租约。窗口和探测超时通过测试专属命名空间HSET检查点输入，无长时间睡眠，不称真实平台故障或Worker杀进程演练。HTTP响应为MockTransport合成数据；返回后报告失败为方法级故障注入。连接拒绝使用本机无服务端口，验证新请求关闭与已有档案回放。
