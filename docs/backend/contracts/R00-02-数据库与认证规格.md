## 2. 类型、归属与实际约束

租户ID为正bigint，对外字符串；业务实体UUID，对外字符串；平台ID另列native_id/native_entity_id。流水事实、审计、投影和AI调用明细可用内部bigint，不能冒充对外实体ID或SSE提交游标。

- 租户业务表的tenant_id为NOT NULL并指向tenants(id)；开启ENABLE+FORCE RLS，事务内参数化set_config，未认证或无有效上下文不能读写业务。
- users是全局受限身份；email_codes、auth_challenges、auth_events、auth_rate_limits是登录前受限表；consumer_inbox是系统消费者表；权限字典/内置角色模板是全局只读。它们不能靠“允许tenant=0”的通用策略开放。
- FK目标必须有对应PRIMARY KEY/UNIQUE；不能依赖“id全局唯一”跳过租户列。实际外键、类型、唯一键、分区键由 `check_database_auth.py` 从13册SQL片段解析核对，不只检查中文说明。
- MATCH SIMPLE允许可选维度整体不参与匹配，所以CHECK还必须约束：sku_id存在时product_id存在，campaign_id存在时account_id存在；entity_kind为SKU/PRODUCT/LIVE/CAMPAIGN/ACCOUNT时相应内部维度必须存在。商品/场次属于同店铺、SKU属于同商品、计划属于同账户和店铺，不能只验证tenant相同。
- UUID列user_id/created_by等引用全局users是允许的单列FK例外，仅证明身份存在；“是否属于当前有效成员且有动作权限”在用例按服务端会话复查。不能把普通users FK当作完整授权。
- polymorphic target_id/biz_id、JSON内引用、raw_ref/sync_run_id等不能声称普通FK已验证；机器清单逐项列出后续所属任务和校验方式，落地该用例前必须完成对应校验。

### 2.1 系统模板只读与选择

保持16册的tenant=0/is_system=true系统模板，无需创建虚构的tenant 0。13册给出的owner_tenant_id是生成列：系统行null，租户行真实正租户FK；CHECK把is_system与tenant_id绑定。租户行写策略同时校验not is_system、当前正租户，UPDATE有USING+WITH CHECK。系统行仅在已有合法正租户上下文时可读，无上下文不开放共享行。

workflow_runs增加template_tenant_id并复合引用模板；它只能等于0或本行tenant_id。这样既允许系统模板，也阻止A租户运行引用B租户私有模板。模板版本只追加、运行保存版本；删除/修改被引用模板由内容卡约束，不在本卡重写SOP业务。此ALTER属于M3对应迁移，不能提前塞到M0空库初始化。

## 4. 认证角色、函数面与会话规则

### 4.1 最小角色矩阵

| 角色 | 运行态 | 可访问 | 禁止 |
|---|---|---|---|
| app_owner | NOLOGIN/NOBYPASSRLS，业务表所有者 | 只经独立迁移SET ROLE创建对象 | 应用继承/SET ROLE；应用持有所有者凭据 |
| app_migrate | 默认NOLOGIN；部署仅维护期间启用独立LOGIN，NOINHERIT | 受控SET ROLE app_owner/auth_fn_owner | API/Worker配置此连接，作为日常业务身份 |
| app_login | 独立LOGIN、非所有者、NOINHERIT/NOBYPASSRLS/NOSUPERUSER/NOCREATEDB/NOCREATEROLE | 逐表业务ACL+RLS；audit_logs仅SELECT/INSERT；系统字典SELECT | 直读认证表；TRUNCATE/REFERENCES/TRIGGER；继承所有者 |
| app_auth | 独立LOGIN、NOINHERIT/NOBYPASSRLS/NOSUPERUSER/NOCREATEDB/NOCREATEROLE | auth schema USAGE及白名单函数EXECUTE | 直接访问基础表、通用跨租户业务查询、SET ROLE |
| auth_fn_owner | NOLOGIN/NOINHERIT/BYPASSRLS，不是通用业务所有者 | 下述认证必需表的最小列/动作 | 业务资产、资金、内容、事实、业务审计、系统inbox；授给运行身份 |

auth_fn_owner权限上限：users SELECT；tenants SELECT(id,status,deleted_at)；memberships SELECT；sessions SELECT/INSERT/按列UPDATE；email_codes SELECT/INSERT/按列UPDATE；auth_challenges SELECT/INSERT/按列UPDATE；auth_rate_limits SELECT/INSERT/按列UPDATE；auth_events INSERT。需要SELECT FOR UPDATE的函数只在已允许按列UPDATE的认证行上加锁；只读users/tenant/membership不为加锁而扩大UPDATE权。清理/分区管理使用另行审批的运维身份，不放进应用.env。

公共函数安全：固定search_path=pg_catalog,pg_temp，表/函数引用全限定；参数绑定，不拼标识符、不接收SQL/任意表名；创建/改所有者/REVOKE PUBLIC及GRANT精确签名同事务。默认PUBLIC函数EXECUTE也按实际创建角色撤销；不能只撤已有函数。直接子分区也不授业务角色权限，防从分区子表绕过父表策略。DDL模板见 [认证参考SQL](r00-02-auth-surface.sql)。

### 4.2 函数签名与前置

机器清单列出准确签名、返回/守卫、允许调用者；只有auth.resolve_session提供参考SQL函数体，其余是待M0实现的接口约束，不伪称已有函数。

| 函数 | 输入 | 最小结果与强制守卫 |
|---|---|---|
| auth.credentials | normalized_email text | 只返回活跃全局user_id/password_hash/规范邮箱；null密码不可密码登录；不存在/错误HTTP同文案 |
| auth.memberships | user_id uuid | 密码/邮件验证成功后的可信用例调用，返回活跃租户成员id/kind/authz_version；不直接暴露HTTP查询任意user_id |
| auth.create_session | user_id uuid,membership_id uuid,token_hash text,csrf_hash text | 仅密码已由可信后端argon2id校验成功后调用；复查用户/租户/成员，SQL侧计算期限和权限版本，插入会话 |
| auth.email_session | challenge_id uuid,code_digest text,membership_id uuid,token_hash text,csrf_hash text | 行锁检查邮件码摘要/有效期/attempts/一次性；服务端从email解析用户；消费+建会话同事务，只能成功一次 |
| auth.resolve_session | token_hash text | 当前有效会话/用户/成员/租户；检查撤销和两种到期，不输出密码/令牌/CSRF摘要；同时返回签发和当前权限版本 |
| auth.renew_session | token_hash text,expected_version integer | 条件更新，重新检查关联身份有效性；滑动到期不越绝对上限；不凭旧Redis身份续期 |
| auth.revoke_session | token_hash text | 幂等吊销PG事实并version+1；不依赖缓存删除是否成功 |
| auth.issue_challenge | email text,code_digest text,preauth_hash text,csrf_hash text | 预认证挑战有效、CSRF匹配、LOGIN用途固定；按邮箱/IP摘要节流；id作为challengeId、重发60秒及每日上限来自服务端配置 |
| auth.issue_preauth | cookie_hash text,csrf_hash text | 短期CSRF挑战，只存摘要；精确来源校验由HTTP用例先做；不是登录成功证明 |
| auth.resolve_preauth | cookie_hash text | 未撤销/未过期挑战；CSRF比较和请求用途检查，不能当业务身份 |
| auth.rotate_csrf | session_hash text,csrf_hash text,expected_version integer | 有效会话+版本CAS；替换摘要使旧令牌失效，冲突不自动重放原写请求 |
| auth.rate_limit | key_digest text,bucket_kind text | 锁定摘要桶、受控窗口/次数更新；未知邮箱也记，不能由客户端任意改变阈值 |
| auth.record_event | email_digest text,outcome text,request_id text,ip_digest text | 未知/失败全局认证事件，tenant/user固定为空；成功登录/已知归属事件由会话函数内部写入已验证身份，不接客户端tenant=0 |

数据库认证角色是可信认证子系统的一部分：数据库函数不可能从“前一次普通Python密码比较”自动推导成功事实。因此不宣称仅凭函数ACL就能防盗取app_auth凭据的人伪造登录；所有者/认证凭据隔离、参数化和不把函数直接映射成HTTP是必要前提。RLS的GUC同样可被持DB凭据者设置，只用于防漏过滤，客户端租户值不得成为其来源。

### 4.3 会话、挑战和撤权

1. Cookie只持随机bearer，数据库存SHA256；CSRF为独立随机令牌的摘要。六位邮件码使用独立pepper的HMAC-SHA256，绑定challengeId/purpose；pepper不在数据库和日志。失败次数、验证码消费、节流全部持久化，不靠单进程内存/Redis唯一事实。
2. 邮件码错误计数必须提交，不能因抛出“密码错误”把次数更新回滚；返回受控结果后由HTTP层转错误。成功消费与会话插入同事务，插入失败必须同时撤销消费；并发同码只能建一个新会话。预认证挑战在成功登录后撤销，新会话令牌轮换。
3. 每次受保护请求先在auth连接重新查PG事实，再由服务端结果打开app_login业务事务。sessions+memberships三列FK防串身份，用户/租户停用、成员移除、会话撤销/过期后下一个请求拒绝。已经通过检查的在途请求不宣称能撤回；资金写在执行前还需R00-03/M2最后复检。
4. 权限修改时membership.authz_version递增。resolve返回issued/current两个版本；若变化，丢弃缓存并重新计算动作和数据范围，旧SSE游标resync。Redis不存在/失效只回PG，不让命中旧缓存覆盖新权限或吊销。
5. 新CSRF接口的HTTP字段沿用R00-01提案，不新增不兼容必填项。切租户重新验证membership并重新签发会话；用户选择只作为候选，不能传tenantId后直接set_config。
6. auth_events的未知邮箱事件tenant_id/user_id可空，邮箱/IP用独立审计摘要；业务成功审计才有真实正租户。数据库唯一/FK错误可能绕过RLS，HTTP不得回显原始SQL或“其他租户对象存在”的细节。

## 5. 指标事实与事件水位

### 5.1 同口径事实键

ux_metric_facts_biz的完整列在机器清单与13册索引中逐项比对，含小时、币种、单位、时区、归因窗口、内部SKU/计划等维度及entity_kind/native_entity_id。NULLS NOT DISTINCT使缺省维度的同键重跑仍幂等；不靠全零UUID/字符串空值冒充缺失。业务ID和平台原生ID不能混用。

MINOR对应CNY且数值为整数，BEAN对应BEAN且为整数；COUNT/RATE/RATIO/HOURS的currency为空。缺失不落零，真实0正常入账。COUNT等范围与退款/修正的允许负值由指标定义，不一刀切所有事实>0。

来源版本已知时只接受更新版本；只有source_updated_at时比较同来源时间，相同时间却内容不同进冲突队列而不是盲覆盖。未知来源版本/时间时，同账户同流同步先串行领取、持久化确认页及批次水位后提交；“抓得更晚”不自动判新。不同来源质量/币种/归因窗口的行不能互相upsert或求和。

### 5.2 投影顺序与SSE游标

顺序：短事务锁event_stream_heads(tenant_id)→查source_event_id是否已投影→重复则返回既有seq→否则head_seq+1并插入投影→同事务提交→事务外发布通知。投影失败必须回滚head，不能让一个较低已分配号晚于高号提交。跨租户互不持同一水位锁。业务资源version独立防旧状态覆盖，tenant_seq只代表投影可见顺序。

正式游标冻结为 `v1.<base64url(payload)>.<HMAC-SHA256>`；payload包含tenantId、membershipId、authzVersion、scopeHash、tenantSeq、issuedAt、keyId，tenantSeq仍序列化字符串。签名密钥与session/email pepper分开保管。14册tenant:seq是旧示意，非新格式的字面约定；F12实现时按本规格联合接线。客户端仅存回传不自行解析。

服务器先从会话确定当前租户/成员/权限，再验签和比对游标范围，不用游标内容建立权限。伪造/跨租户游标拒绝；权限/范围变化发既有resync事件；tenantSeq大于当前head或小于retained_from_seq-1也resync。首次无游标按F12方案先读快照再建立补发边界，不能假定现有subscribe已经实现。

读取时固定已提交上界H，按当前数据范围过滤且seq<=H分页。返回满页时游标只到末条已发送seq；确认该页已穷尽到H才可发范围绑定的checkpoint到H。过滤造成序号间隔不等于丢事件，不能因跳号直接报错；不能先把游标推进head再忽略剩余页。保留7天，由维护流程在同租户锁内更新retained_from_seq并删除旧投影；无匹配事件也可保留心跳，不能泄露别的范围payload。

## 6. API/Worker唯一业务实现

| 层 | API | Worker | 共同约束 |
|---|---|---|---|
| 领域 | 调纯Python规则 | 同一模块同一函数 | 无数据库/框架/HTTP依赖，不复制风控 |
| 数据库用例 | AsyncSession事务中await run_sync(同一个同步Session用例) | 同步Session事务中直接调用同一用例 | 最先参数化设置服务端租户；状态/预占/outbox原子提交；失败回滚 |
| 外部IO | async httpx等 | 同步适配器或独立事件循环 | 平台/LLM/Redis/SMTP不放run_sync、DB锁或事务中 |
| 生命周期 | 连接池按API进程创建/关闭 | prefork子进程启动后建池 | 不共享Session、不跨进程继承连接、不在同Session并发跑协程 |

因此“异步API、同步Worker”不是两套风控；不同的是会话工厂/IO适配。架构导入检查、同用例正反例、API与Worker真实PG事务/回滚一致性留给M0/M2，不能拿本卡说明代替运行证据。

## 7. 验收层级与后续真实检查

本卡D类检查：从13册解析FK/目标唯一键/列类型/分区键/事实键，核对机器清单与文档，逐函数最小权限/守卫、迁移DAG、事件顺序和单实现决定；通过修改副本的负例确认检查会拦漏FK、越权角色等错误。检查无后端依赖，无真实凭据。

M0/M1/M4真实用例至少包括：空库升级两次；A→B连接复用及异常回滚；跨租户/同租户跨店铺/跨商品外键拒绝；系统行读允许写拒绝；认证未知邮箱/错误码/次数提交/并发一次消费；停用/撤销与Redis旧缓存；分区落库及只追加审计；NULL维度幂等与旧页冲突；双事务提交顺序/重复投影/分页/过旧游标/权限变更resync。详见机器清单acceptanceCases，本卡全部标为PLANNED_REAL_TEST，未计通过。

## 8. 依据

- [PostgreSQL 17约束](https://www.postgresql.org/docs/17/ddl-constraints.html)：被引用列必须有适当唯一性，复合FK与NULL语义。
- [PostgreSQL 17 RLS](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)：所有者/BYPASSRLS例外，完整性检查不能替代安全隔离。
- [PostgreSQL 17安全函数](https://www.postgresql.org/docs/17/sql-createfunction.html)：安全search_path、PUBLIC默认EXECUTE与同事务授权。
- [PostgreSQL 17分区](https://www.postgresql.org/docs/17/ddl-partitioning.html)：分区唯一键包含分区列；本卡未实跑分区。
- [PostgreSQL默认权限](https://www.postgresql.org/docs/17/sql-alterdefaultprivileges.html)：实际创建角色的默认函数权限需独立撤销。
- [SQLAlchemy run_sync](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html#running-synchronous-methods-and-functions-under-asyncio)：同步Session用例在async路径的受控调用，不能混入任意阻塞IO。
