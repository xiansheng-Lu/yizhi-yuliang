# ADQ／微信小店独立项目安全修复包

2026-10-28。对应接入前四项问题，范围为两个独立项目的令牌基础设施。
原目录不是 Git 仓库，因此在驭量仓库保存可复用补丁、逐文件摘要、应用工具和验证记录，
不复制真实配置、令牌、经营数据或整个独立项目，不将这些项目伪装成已接入的驭量连接器。

## 已修复

| 问题 | 最终实现 | 核对证据 |
|---|---|---|
| ADQ state 缺省绕过 | state 必填、随机签发、短期有效、一次性消费；绑定服务租户、应用、可信后端传入的发起人及固定 HTTPS 回调；拒绝客户端覆盖 | test_oauth_security.py：空值、无效值、重放、过期、应用错配、无 API Key、缺发起人、回调和轮换凭据测试 |
| 明文令牌及可选鉴权 | AES-GCM 密文信封、key_version、身份上下文认证、私有密钥环；raw token/刷新/授权管理强制 API Key；不匹配、篡改或旧明文文件拒绝读取；提供显式离线迁移工具 | test_security.py：往返、无明文、跨租户/应用、篡改、未知版本、缺配置、nonce、初始化/迁移、缺 API Key 启动拒绝 |
| 仅线程级刷新保护 | 每个指定数据目录/缓存路径一个进程独占锁，从导入到进程退出持有，第二进程拒绝；缓存先发布成功/失败状态再释放 in-flight；ADQ 轮换 refresh_token 加密写回 | 原缓存并发测试、真实子进程互斥/释放测试、迁移遇活动 owner 不改文件、两套 mock 冒烟 |
| 微信小店第二条隐式取 token 路径 | SDK、面板采集器、只读探针默认走已鉴权托管服务；显式独立直连模式严格用响应 expires_in，并发合并，即便微信返回同一个 token | test_token_provider_security.py：默认服务入口、传输/鉴权、短 TTL、无效 TTL、20 并发只请求一次 |

权限边界：X-Actor-ID 必须由可信后端从真实登录会话取得，本独立服务不验证驭量用户登录。
部署边界：单机本地文件系统、同一应用指定唯一数据目录/缓存路径、单进程单 worker。
多机/独立数据目录不共享锁，必须共同访问唯一托管服务，不能部署多个刷新者。
生产 API Key 和密钥环需通过私有部署配置提供；测试只用合成凭据。

## 检查及应用

先安装独立项目 requirements.txt（新增 cryptography）。以下默认只校验，不改文件：

```powershell
python backend/tools/token-service-hardening/apply.py tencent-adq D:/codex/tencent-adq
python backend/tools/token-service-hardening/apply.py wx_shop D:/codex/wx_shop
```

实际源目录已应用本次修改，上述命令会输出与验收版本一致。
其他基线副本需要应用时追加 --apply。工具先核对全部源文件摘要，再 git apply --check，
源文件变化或部分应用时拒绝覆盖；换行符差异按 UTF-8 规范化比较。
