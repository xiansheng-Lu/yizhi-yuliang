## 三条DoD

1. 随机高熵state只保留带服务端密钥的HMAC，绑定原管理员、租户、原会话、应用/连接器、固定回调摘要及有效期。PG原子消费支持多进程竞争，重用/篡改/过期/应用或回调替换均拒绝，失败或结果未知均不能用原state自动重换码。采用PG持久化state以便单次领取与授权记录关联，未采用07册初稿的Redis存放示意；待BE复核该实现选择。
2. 回调不接受来自另一设备的身份/Cookie，而由受限definer函数按不可枚举HMAC恢复原身份。原会话、成员/用户/租户、connection.manage权限和ALL_TENANT管理范围必须有效；换码前及提交令牌时再次检查。原会话注销或权限撤销不能借新设备会话继续。实际测试清空浏览器测试客户端Cookie，仍按DB中的原有效会话完成；不称真实OAuth浏览器跳转验收。
3. 换码端口在数据库事务外执行，开始事实先提交，平台超时有上限且不自动重试。密文、授权、成功事件与state终态一起提交；失败、取消、存档权限故障或途中撤权不留半有效授权。AES-256-GCM使用随机nonce，AAD绑定租户/授权/应用/产品/令牌种类/密钥版本；key_version明确存储，轮换保留旧密钥解密并用当前密钥重新加密，令牌更新与轮换审计同事务。旧钥缺失、密文篡改、跨上下文替换均拒绝，密钥不入库或Git。
