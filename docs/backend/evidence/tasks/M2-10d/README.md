## 实现与三条DoD

1. 0035把原预算完整观察函数收为内部budget_initialize_snapshot并撤销运行身份EXECUTE，原入口增加治理包装，仍使用已提交完整来源和原权限/字段/覆盖检查。外部变化按实际全量组件替换B，保留全部在途R；即使B+R已超限也入账。budget_discrepancies保留前值、实际观察值、来源时钟、批次摘要及原始出站引用，budget_alerts持久记录OVER_LIMIT/RECONCILIATION/STALE_SOURCE，作为后续F07读取的本地告警事实，不宣称已经向外部渠道发送通知。重复快照不新增差异或重复告警。
2. 新完整来源若较已确认E2更旧，不能把已核验组件改回旧值，也不能凭较旧空列表抹掉已确认配置。包装函数用子事务回滚该次B替换，保留此前B/R和独立已提交的原始同步档案，另落STALE_SOURCE/冻结，返回snapshotApplied=false。Source/Fetched时钟遵从各来源合同。正常完整列表中已消失的组件记0，删除证明引用新批次终页；不会用旧响应冒充删除证明。与当前未终结执行相容的新值只记OWN_PENDING兼容观察，R仍不动；明确受理后的不同观察值另记INFLIGHT_MISMATCH/OPEN并冻结，不提前按核验窗口判死或释放。
3. 对账resolve必须引用相关原申请已实际完成的budget_job_finalizations，验证E2匹配或实际平台拒绝E1、证明不早于差异、当前完整预算来源/策略与HELD合计一致，才将相应差异定性。B/R本身只由真实完整观察或M2-10c终结服务改变，resolve不接手填金额。没有其他OPEN差异时才解除RECONCILIATION；仍超限则保留OVER_LIMIT，其他冻结原因不擅改。差异、来源档案、终结账保留，不能删差异后解冻。四并发resolve只有一次实际定性和解冻，重复证明只复用已定性事实。

增额会在CREATE和EXECUTE实际复核新B/R，已批准旧单不能借原审批绕过新超限。UnsentBudgetRejection只允许仍APPROVED、未领取、无dispatch、无执行单的正预算增额，重新运行实际EXECUTE风险并确认AMOUNT_LIMIT失败；新增内部UNSENT_REJECT边将原申请FAILED、error=RISK_BLOCKED/retryable=false、无平台回执，同时按严格E1未发送证明释放R。风险、申请/事件、释放、终结账与两类审计同Session原子提交。已经SENT/状态变化、额度未拒绝或原单已过期均不允许用此入口关闭；不能把外部未知当未发送。此边不新增公开任务状态，也不伪造command_job。后续Worker/生命周期HTTP装配此服务，不在本卡开放真实平台写。

RECONCILIATION下明确减额/暂停仍可通过额度类纠偏检查，但必须有当前完整来源，并继续受资格、频率、目标守卫等全部检查；较旧来源造成basis不当前时仍阻断。资金增加、扩大消耗不能借此豁免。
