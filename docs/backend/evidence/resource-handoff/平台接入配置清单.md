## 两个平台分别确认的范围

### ADQ

1. 填平台后台真实应用类型/授权方式，不从应用名推断广告主自用或服务商模式。
2. 列实际批准的scope代码。首批期望只读能力是账户与计划、资金/操作记录、日报；这些是业务能力名称，不是我猜测的官方scope代码，需按后台实际结果映射。
3. 对每个试点广告账户说明所属业务租户、店铺、授权关系及只读试点范围；应用scope不等于所有账户均已授权。
4. 如该应用额外要求固定出口IP/IP白名单或其他接入限制，一并提供后台要求与现有配置状态；未要求的项目标“不适用”。

### 微信小店

1. 提供后台实际接入模式与该模式的官方接口/权限依据。自营应用与服务商授权的资料按实际模式准备，不直接套ADQ流程。
2. 说明已授权店铺、经营主体、应用之间的关联，以及授权是否已生效、有效期/续期方式。
3. 首批期望只读能力为商品/SKU/库存、订单/经营数据、直播经营数据及适用资金/结算口径；逐项列实际允许的接口。未开放的项目明确标“未开放”，不填全量权限。
4. 回调校验Token、消息加解密材料等，仅在实际模式/后台明确要求时通过私有渠道提供；不要为未采用的模式额外准备凭据。

微信小店经营授权不代表ADQ广告写权限，也不代表小店推、微信豆或其他产品线资金权限。

## 本地交接方式

非敏感模板见 [platform-inputs.template.json](platform-inputs.template.json)。可复制到仓库已忽略的目录，再填实际资源：

```powershell
New-Item -ItemType Directory -Force .runtime/platform-config
Copy-Item docs/backend/evidence/resource-handoff/platform-inputs.template.json .runtime/platform-config/inputs.local.json
git check-ignore .runtime/platform-config/inputs.local.json
```

应用Secret等原文另存该忽略目录的私有文件，或使用已有密钥管理器；`secretMaterialRef`只写本地路径/条目引用，不写密钥。只需告知私有配置的路径或引用，我再核对、接入和脱敏记录，不用把原文贴在聊天或提交Git。

模板中的`null`表示“尚未提供”，不能把它改成空数组后声称已验证无数据/无权限。请保留原生ID的完整值用于本地映射，进入证据/仓库前由我脱敏。

**不要把模板字段直接追加到当前`backend/.env`。** 现有Settings尚未声明平台专用配置，且拒绝额外字段；本模板用于资源收集，接线完成后再给出实际运行配置。已有后端数据库、Redis等本地配置无需重新提供。
