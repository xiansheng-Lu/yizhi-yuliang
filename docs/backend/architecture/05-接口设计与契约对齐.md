# 05 接口设计与契约对齐

R00实施基线：现有V1/V8/V9/分析路径矩阵、源码版本、黄金样例及CSRF/V9异步素材差异见[冻结决定](../contracts/冻结决定.md)。新增异步上传使用独立任务路径，F11接线前不得改变现有materials返回SelectedResource的约定；两端尚待复核的新增项不作为已联调通过。

本册规定后端 HTTP 接口的通用约定，并逐一映射前端已有四份契约。原则：**前端已经在按这些路径和字段发请求，后端优先适配既有契约，不重新发明一套让前端返工**；契约缺口（分页、订阅、对账）在既有命名空间内补齐。

## 1. 通用约定

### 1.1 基础

- 版本前缀：一期全部 `/v1/`；破坏性变更升 `/v2/` 并在过渡期并存。
- 请求与响应：JSON（UTF-8）；文件上传 multipart/form-data；AI 流式 text/event-stream。
- 会话：Cookie 携带，前端固定 `credentials: "include"`；CORS 精确白名单（本地 `http://127.0.0.1:3000`，生产具体域名），不放通配。
- 请求头：写请求带 `X-Yuliang-Client: web`；CSRF 用双重提交令牌（Cookie + `X-CSRF-Token` 头，详见 09 册）。
- 超时：接口设计目标 15 秒内返回（与前端超时一致），平台慢操作一律转任务，不占着 HTTP 连接等平台。

### 1.2 成功信封

沿用前端既有信封，不改动：

```json
{
  "schemaVersion": "command-job-v1.0",
  "requestId": "后端生成的唯一请求标识",
  "data": {}
}
```

说明：当前 `ApiClient.request()` 对所有命名空间的**外层** `schemaVersion` 固定校验为 `command-job-v1.0`。V8/V9 在 `data.contractVersion` 分别使用 `delivery-v8.0`、`advertising-v9.0`、`platform-workspace-v9.0`；分析结果在 `data.schemaVersion` 使用 `business-analysis-v1`。不得把内层版本写到外层。`requestId` 每次必返，与日志、Worker、平台调用链路贯通。202 等成功响应同样返回该 JSON 信封；退出返回 200、data=null，不返回空 204。

### 1.3 失败信封与 HTTP 状态

```json
{
  "requestId": "...",
  "error": {
    "code": "CONFLICT",
    "message": "可直接展示给用户的中文说明",
    "details": [{ "field": "amount", "reason": "超出单次变动幅度" }]
  }
}
```

| HTTP | code | 触发场景 | 前端既有处理 |
|---|---|---|---|
| 400 / 422 | INVALID_INPUT | 参数校验失败、字段组合非法 | 保留输入、就地提示 |
| 401 | UNAUTHENTICATED | 未登录或会话失效 | 清缓存、跳登录 |
| 403 | FORBIDDEN | 已登录但无动作权限或数据范围 | 提示联系管理员 |
| 404 | NO_DATA | 资源不存在；V8 约定新接口未接入也可用 404 表达"待接入" | 新投放接口 404 时前端走只读适配，不转 Mock |
| 409 | CONFLICT | 乐观锁版本冲突、幂等键绑定了不同载荷 | 回显服务端最新版本，要求重新核对 |
| 423 | LOCKED | 结果未知期间重复提交被锁定 | 禁止重放，引导查询；当前客户端尚未映射，需 F01 改造 |
| 429 | RATE_LIMITED | 限流，带 `Retry-After` 秒数 | 按秒退避 |
| 502/504 | UPSTREAM_ERROR / TIMEOUT | 平台或依赖异常、超时 | 按结果未知处理，不回退演示 |

前端既有错误码集合还包括 NETWORK_ERROR、INVALID_RESPONSE、API_NOT_CONFIGURED，这三个由前端传输层产生，后端不返回。当前客户端只按 HTTP 状态映射通用错误，尚未读取服务端 code/details/current；表中细分业务提示和冲突资源回显须完成 19 册 F01 才成立。正常的"空业务集合"返回 200 + `[]`，不用 404；空数据与未接入严格区分。

### 1.4 分页、排序与过滤

- 列表接口统一游标分页：`?cursor=&limit=`，响应 `{ "items": [], "nextCursor": null }`；前端创编 options 已按 LookupPage 设计（cursor 续拉）。
- 兼容前端任务列表等现有数组响应的接口不强行改分页；新增列表一律游标。
- 过滤参数显式声明，不接收任意 key 透传平台；时间参数 ISO 8601 带时区，日期参数 `YYYY-MM-DD` 按北京时间。

### 1.5 幂等与版本

- 所有写接口接受客户端 `idempotencyKey`（创建类必传）；同租户同接口同键返回首次结果；键与载荷绑定不一致返回 409。
- 资源更新接受 `expectedVersion`，版本不符返回 409 并带最新资源。
- 撤回类操作携带原创建键 + 新撤回键（V9 约定），原键永久保留用于查询，不复用。

## 2. 认证与身份接口（G1-A 契约）

| 方法路径 | 请求 | data |
|---|---|---|
| GET `/v1/auth/session` | Cookie | Identity（未登录 401） |
| POST `/v1/auth/login` | `{email,password}` 或 `{email,code,challengeId,method:"email_code"}` | Identity |
| POST `/v1/auth/email-codes` | `{email,purpose:"LOGIN"}`（当前ApiClient实际请求） | `{challengeId,expiresAt,retryAfterSeconds}` |
| POST `/v1/auth/logout` | - | null |
| PATCH `/v1/users/me` | `{displayName}` | Identity |
| GET `/v1/auth/csrf` | - | `{csrfToken}`（首期页面加载时随会话下发也可） |

Identity 字段保持前端定义：`userId/displayName/email/tenantId/shopIds/permissions/workspacePages/mode`。后端输出 `mode:"API"`，永不输出 MOCK 身份。

会话相关：

- 会话事实存 PostgreSQL（sessions 表），Redis 仅缓存；Cookie 为 HttpOnly、Secure（生产）、SameSite=Lax；活动续期滑动，长期不用过期，服务端可即时吊销。
- 多租户成员登录后返回默认租户与可切换租户列表（接口预留 `GET /v1/auth/tenants`、`POST /v1/auth/switch-tenant`，前端可后续接入）。
- workspacePages 由权限点推导（见 04、09 册），保证页面授权与动作权限是同一真相。

## 3. 快照与范围接口

| 方法路径 | 说明 |
|---|---|
| GET `/v1/frontend/snapshot` | 返回 FrontendSnapshot 全量结构（tenants/shops/adAccounts/liveSessions/plans/products/materials/tasks/scope/riskPolicies/replaySegments/replayReports/connectors），`source:"API"` |
| PUT `/v1/frontend/reporting-scope` | 保存当前 ReportingScope（会话级 + 按用户持久化） |

快照是 G1-B 联调期的聚合接口，后端按授权范围组装，数据来自各镜像表与事实表；它是读模型，不承载写入。数据量上来后逐步把各集合拆为独立分页资源，快照接口保留给中枢首页首屏，字段只减不增需提前协商。

当前快照的十二个集合必须保持数组，不能改成 `{items,...}`；`revision`、`schemaVersion`、`source`、`scope` 一并返回。G0 就提供合法空数组快照，保证登录后的工作区不依赖平台已接入。兼容期只服务可返回完整快照的受控范围，超上限返回明确业务错误并限制试点规模，不静默截断或冒充全量。

规模扩展须先联合升级分页资源、快照完整性元数据与前端消费者，再开放大账户；概况同步完成 19 册 F04，改读完整服务端范围聚合。目前 `loadSnapshotOverview` 仍使用单日数组本地汇总，仅新增后端聚合接口不会自动改变前端行为。

`connectors` 集合按前端 Connector 结构输出（id/status/scopes/checkedAt），状态来自能力聚合：任一执行能力六阶段全通才给 SUPPORTED，部分只读给 READ_ONLY，无授权 UNKNOWN，异常 DEGRADED。

## 4. 中枢与指令任务接口（command_job V1.0）

| 方法路径 | 对应前端方法 |
|---|---|
| GET `/v1/workspace/history` | 项目、对话、任务归类 HistorySnapshot |
| POST `/v1/projects` | createProject |
| PATCH `/v1/conversations/{id}` | moveConversation，body `{projectId}` |
| POST `/v1/conversation-messages` | sendMessage（含消息幂等键，返回 turn + interpretation） |
| POST `/v1/conversations/{id}/jobs` | attachConversationJob，body `{messageId,jobId}` |
| PUT `/v1/command-jobs/{id}/project` | assignTaskProject，body `{projectId}` |
| POST `/v1/command-interpretations` | interpretCommand（独立解析入口，保留） |
| POST `/v1/command-jobs` | createJob |
| POST `/v1/command-jobs/{id}/confirm` | confirmJob |
| POST `/v1/command-jobs/{id}/approvals` | reviewJob，body 含 decision |
| POST `/v1/command-jobs/{id}/cancel` | cancelJob |
| PUT `/v1/risk-policies/{id}` | updatePolicy（带 version） |

实现要点：

- 创建任务时后端自行回读 old_value 并执行风控，返回 DRAFT 或 BLOCKED；直播开关播在无推流授权时直接落 MANUAL_REQUIRED。
- confirm/approvals/cancel 全部带 expected_version，状态合法性由 06 册状态机裁决。
- AUTOPILOT 来源任务只接受 Worker 内部调用（内部服务令牌），对外接口收到 AUTOPILOT 一律 400。
- AI 解析输出必须是 QUERY/ACTION/UNRECOGNIZED 三选一的合法结构；ACTION 多候选只回候选 ID 列表，由用户消歧。
- advanceMockJob/expireMockJob 等 Mock 专用方法不提供真实接口；对应的真实推进由 Worker 完成，前端通过刷新或事件订阅读取。
- 补充查询接口：`GET /v1/command-jobs?cursor=&limit=`（默认 50、上限 100、稳定排序）、`GET /v1/command-jobs/{id}`、`GET /v1/command-jobs/{id}/attempts`（执行尝试、平台回执脱敏信息、历次核验时间线；人工核对动作单独权限，且只记录核对依据，不提供"改成功"操作）。
- 状态事件：`GET /v1/events`（SSE，支持 Last-Event-ID 续传，详见 03 册 6.4）；事件只通知实体与版本变化，前端去重、防乱序并合并短时间重复刷新后，按权限重读资源。429/5xx 不自动重放写请求，事件中断回退轮询。

## 5. 投放管理接口（V8 契约 `/v1/delivery/*`）

### 5.1 工作区与能力

`GET /v1/delivery/workspace?platform=&shopId=&accountId=&start=&end=&liveSessionId=`

返回源码 `src/lib/delivery.ts` 的 DeliveryData：`scope/source/shops/accounts/capabilities/plans/goals/decisions/budgets/funds/executions/approvals/boundaries/trends/budgetTrends/sync`，`contractVersion:"delivery-v8.0"`，业务数组严格按 scope 过滤。不得用 campaigns/promotionOrders/allocations/policies 替换前端要求的集合；不同平台业务对象在适配层映射成正确的 Plan。

能力对象 actions 覆盖 12 个动作（create/budget/bid/pause/resume/review/analyze/goal/allocate/verify/retry/rules），每项 `{status,reason,permission}`；并返回 execution、automationMode、refreshSeconds、maxAgeSeconds、supportedObjects/Metrics/Filters/Columns、schema（objectives 必须真实、targets、bidEditable、minAmount/maxAmount）。**前端不硬编码任何平台枚举**，objective 等全部取该对象。

### 5.2 写入接口清单

| 方法路径 | 用途 |
|---|---|
| POST `/v1/delivery/campaigns` | 新建计划（ADQ 等） |
| POST `/v1/delivery/promotion-orders` | 新建加热订单（微信豆/DOU+ 订单式） |
| POST `/v1/delivery/plan-changes/preview` | 变更预检，返回 RiskPreview（token、expiresAt、checks、requiresApproval、expectedVersion） |
| POST `/v1/delivery/plan-changes` | 携带 previewToken 的正式提交，返回 MutationResult |
| POST `/v1/delivery/goals` / PATCH `/v1/delivery/goals/{id}` | 经营目标创建/调整 |
| POST `/v1/delivery/budget-requests` | 预算分配新建/调整（planId 或 accountId，parentAllocationId 可空） |
| POST `/v1/delivery/analyses` | 投放 AI 分析（kind: GOAL_GAP/PLAN/DECISION/BUDGET/EXECUTION） |
| POST `/v1/delivery/decisions/{id}/reviews` | 决策处置 APPROVE/REJECT/DEFER/MODIFY |
| POST `/v1/delivery/approvals/{id}/reviews` | 通用审批 APPROVE/REJECT |
| PUT `/v1/delivery/policies` | 账户自动化策略 |
| POST `/v1/delivery/executions/{taskId}/verify` | 仅回读核验，不重放 |
| POST `/v1/delivery/executions/{taskId}/safe-retry` | 仅在 safeRetry=true 且 FAILED 时出现，后端重新裁断 |

MutationResult 统一：`{resourceId, state, executionId, approvalId}`；受理类返回 202。state 是后端流程状态，不是平台成功标志。

### 5.3 关键校验

- previewToken 绑定用户、账户、对象、前后配置、版本、能力版本、有效期；正式提交时后端重新全要素校验，不信任 token 之外的载荷。
- 微信豆金额单位 BEAN、不接收 ADQ 出价字段；微信豆写能力未证实前 `actions.create.status = NOT_INTEGRATED/NOT_APPLICABLE`、`execution=MANUAL`。
- funds 分币种独立返回，不提供汇率换算字段。
- 接口未接入时按 V8 约定响应，前端保持旧快照只读且显著提示，后端绝不以 Mock 数据应答。

## 6. 多平台创编与资源接口（V9 契约）

### 6.1 配置工作台 `/v1/delivery/configuration/`

| 方法路径 | 用途 |

| GET `capabilities` | 完整 ConfigurationContext 驱动的字段能力（capabilityVersion、有效期、字段状态/单位/规格） |

| POST `audience-estimates` | 覆盖估算（仅 estimateSupported 时可调） |

| POST `validations` | 全量校验，一次性返回 validationToken |

字段六态（PUBLIC/AVAILABLE/API_PENDING/AUTH_REQUIRED/NOT_APPLICABLE/UNCONFIRMED）按上下文返回；预算金额字符串十进制由后端按能力版本换算最终单位。

### 6.2 平台资源 `/v1/delivery/integrations/`

| 方法路径 | 用途 |
|---|---|
| GET `context?productLine=` | IntegrationContext（主体/店铺/账户/多对多 links/能力与凭证） |
| POST `queries` | 只读资源查询（campaigns/adgroups/promotionOrders/creatives/funds/products/orders/lives/compass/...） |
| POST `previews` | 变更预览（原值/目标值/校验/审批/token） |
| POST `commands` | 审计网关提交（previewToken + 幂等键） |
| GET `commands?scopeKey=&idempotencyKey=` | 申请回读 |
| POST `commands/{taskId}/cancellations` | 仅撤回后端标记 cancellable 的未执行申请 |

PlatformResourcePage 每行带 scopeKey；行内只放原生 ID、名称、状态、版本、允许的指标、归因窗口、资金类型；个人信息与未知字段在适配器层丢弃。报表参数必须含 syncedAt/timezone/granularity/attributionWindow/refundHandling/deduplication/warnings。

### 6.3 平台产品线路由纪律

- 上下文必须完整：product（产品线）→ entity → account → shop → objective → target，后端拒绝跨产品线 ID 互换（DOU+ 订单 ID 不得用于项目/单元接口）。
- 聚光未核验路径的创编动作返回 NOT_INTEGRATED，前端只存草稿；千川无专属路径时 operations 为空数组。
- 微信小店 resources 全部是经营类（products/stock/orders/compass/funds/settlements/aftersale），不进入广告计划表，联盟计划不映射为广告 Campaign。

## 7. 经营分析与复盘接口

`/v1/business-analysis/*`（沿用前端 AnalysisAdapter 路径）：

| 方法路径 | 用途 |
|---|---|
| POST `/tasks` | 创建分析任务（query + 维度 + 幂等键）→ queued |
| GET `/tasks/{id}` | 状态轮询（前端每秒一次、最多约 120 秒，后端正常任务应远早于此完成） |
| GET `/results?taskId=` / `/results/{id}` | 不可变结果 |
| GET `/drafts` / GET/PUT `/drafts/{id}` | 草稿列表与乐观锁保存 |
| POST `/drafts/{id}/publications` | 固定版本发布（同草稿版本重复发布用同幂等键） |
| GET `/publications` | 发布历史 |
| GET `/publications/{id}` | 已登录工作区读取固定发布版本；与公开 token 阅读不同 |
| GET `/p/{publicToken}` | 客户阅读链接（免登录、凭 token、可吊销、可设过期） |

服务端职责：日报/周报/月报的数据周期由后端校验（1 天、连续 7 天、完整自然月），不满足直接拒绝；比率类趋势由分子分母重新汇总；AI 诊断字段标注 insightSource；发布返回正式可访问 URL，前端不自行拼地址。分析任务的外部状态固定为 `queued/running/succeeded/failed`，数据库内部大写枚举经适配器转换。当前 results/drafts/publications 列表返回数组，不擅自改分页对象。报告 HTML 导出可由后端渲染固定模板（Jinja）并存对象存储，与发布链接同源管理。

| POST `/v1/connections/{id}/refresh`、`DELETE` | 手动重授、断开（断开前返回影响面供前端确认） |
| GET `/v1/connections` | 已连接账号（授权范围、到期、同步状态，绝不返回 token） |
| GET `/v1/events` | SSE 状态事件订阅（任务/审批/核验/同步），Last-Event-ID 断线续传，鉴权后按数据范围过滤，详见 03 册 6.4 |
| GET `/healthz` / `/readyz` | 存活与就绪（DB/Redis/RabbitMQ 连通性），供 Nginx/运维使用 |
| GET `/metrics` | Prometheus 指标，仅内网 |
| `/admin/*` | SQLAdmin 后台，独立鉴权 |

## 10. OpenAPI 与契约一致性保障

- FastAPI 按模块产出 OpenAPI，CI 中加一道契约检查：用现网导出的 openapi.json 与前端 `docs/shared/contracts` 中的路径/关键字段做差异比对，意外删改路径或必填字段直接让 CI 失败。
- 对前端响应的 Pydantic 模型按契约分组维护（`schemas_command_v1.py`、`schemas_delivery_v8.py`、`schemas_configuration_v9.py`），字段名通过序列化别名精确匹配前端（蛇形/驼峰各自正确），不用全局统一命名策略糊弄。
- 集成测试中录制前端典型请求（创建任务、预览变更、创编校验、分析任务）作为契约黄金样例，回归时比对信封、枚举与状态。
- schemaVersion 只在载荷真实变化时升版；升版必须同步修改契约文档与前端，并在旧版本保留期内同时支持。
