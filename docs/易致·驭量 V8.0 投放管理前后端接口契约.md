# 易致·驭量 V8.0 投放管理前后端接口契约

日期：2026-10-22，时区 Asia/Shanghai。范围仅为现有前端增量重构。

**状态说明：本文不表示广告平台或后端接口已经上线。** 仓库是 Next.js 前端，未新增 Route Handler、服务端投放执行、数据库或爬虫。开发环境沿用明确标识的 mock 模式；没有真实平台联调证据。

## 1. 项目审计与接口差异

审计入口：`src/lib/routes.ts`、`src/features/workspace-entry.tsx`、`src/features/business-page.tsx`、`src/features/control-workspace.tsx`、`src/components/task-controls.tsx`、`src/services/api-client.ts`、`src/services/contracts.ts`、`src/lib/domain.ts`、`src/lib/command-job.ts`。

现状：五个页面原先由通用 BusinessPage/ControlWorkspace 渲染，经营目标是企业风控规则表单；计划页有常驻操作申请；AI决策展示人工任务；预算页复用人民币风控预算。快照没有微信豆加热订单、真实余额、目标时间序列或AI证据模型。现有设计采用白色内容容器和品牌蓝色 Token，继续复用。

## 2. 通用传输、身份和隔离

继续使用现有 ApiClient 的 cookie 会话、`credentials: include`、`cache: no-store`、15秒超时、JSON校验及401失效通知。未新增浏览器令牌持久化。写请求保留 `X-Yuliang-Client: web`，后端必须继续校验会话、CSRF、租户、业务对象归属和操作权限。

外层响应沿用既有封装，便于复用传输层：

```ts
{ schemaVersion: "command-job-v1.0", requestId: string, data: T }
```

新增投放聚合响应 `data.contractVersion` 必须为 `delivery-v8.0`。新路径是**建议契约且前端已声明调用入口**，不是现有后端事实。后端若使用其他网关路径，需要共同修改 DeliveryService。

统一范围：

```ts
type DeliveryScope = {
  platform: "all" | "adq" | "beans";
  shopId: string | "all";
  accountId: string | "all";
  start: string; end: string; // YYYY-MM-DD，含首尾，Asia/Shanghai
  liveSessionId?: string;
};
```

租户和用户来自服务端会话，不能信任客户端传入身份。层级为经营范围 → 交易店铺 → ADQ/微信豆渠道 → 实际投放账户 → 计划/订单。微信小店不作为同类广告平台；不把 wxpromo、千川或聚光重命名为 ADQ/微信豆。

切换平台保留店铺、清除不兼容账户和对象选择。请求同时携带范围，响应必须原样回显范围。前端使用 AbortController + 请求代次校验，丢弃旧账户延迟成功和失败。服务端仍须独立实施隔离。

## 3. 统一响应对象与统计口径

完整、可编译的字段定义位于 `src/lib/delivery.ts`；请求定义位于 `src/services/delivery-service.ts`。以下是交接索引，不替代源码类型。

| 对象 | 主要字段 | 含义与限制 |
|---|---|---|
| Platform | adq / beans | 全平台仅为管理范围，不是原生广告渠道 |
| Shop | id/nativeId/tenantId/name | 业务ID与原始ID分开；旧快照未提供原始店铺ID时为null |
| AdAccount | id/nativeId/shopId/platform/authorization/currency | 单个店铺可关联多个账户；授权由后端声明 |
| PlatformCapabilities | accountId/platform/version/checkedAt/actions/schema/supportedObjects/supportedMetrics/supportedFilters/supportedColumns | 账户级能力、业务对象、指标、筛选、列、新建/修改/审批及参数约束；缺失不放行 |
| Campaign | id/nativeId/accountId/shopId/version/kind=CAMPAIGN/platform=adq/level/budgetMinor/bidMinor/targetRoi | level=CAMPAIGN/ADGROUP/AD；金额为CNY分；保留扩展字段 |
| PromotionOrder | kind=PROMOTION_ORDER/platform=beans/contentId/contentType/heatingGoal/amountBeans/progress/startsAt/endsAt/extensions | 以视频或直播加热订单为中心，额度为整数微信豆，不能沿用ADQ出价字段 |
| PerformanceMetrics | spend/attributedGmvMinor/conversions/roi/attributionWindow/statisticDate/comparableKey | spend按所属平台原生单位；GMV为CNY分；null表示未知；0为实际零值 |
| BusinessGoal | id/nativeId/shopId/platform/accountId/name/period/start/end/status/version/gmvTargetMinor/budget/currency/roiFloor/actualBusinessGmvMinor/spent/actualRoi/breakdown/trends/history | 目标类型日/周/月/直播/店铺；全店支付GMV不等于广告归因GMV |
| GoalBreakdown | id/type/targetId/name/amountMinor | type=SHOP/PLATFORM/ACCOUNT/PLAN/LIVE；targetId必须真实；金额总和不得超过目标 |
| BudgetAllocation | id/accountId/planId/version/currency/limit/allocated/spent/internalStatus/platformStatus/verificationStatus/approvalId/executionId | 内部方案、平台预算修改和核验三种状态分别记录；不是账户资金划转 |
| AccountFunds | accountId/balance/currency/syncedAt/warning | 真实账户余额，未提供显示--；不得以计划预算代替余额 |
| AIDecision | id/platform/accountId/planId/goalId/type/explanation/recommendation/risk/status/evidence/observation/proposedAction/proposedValue/approvalId/executionId/outcome/version | 必须保留证据ID、样本、观察区间、延迟、可信度、限制；不把人工任务伪装为AI判断 |
| ApprovalRequest | id/decisionId/budgetId/executionId/status/actorId/version | 可追溯审批及关联关系，不能仅用视觉跳转 |
| ExecutionTask | id/nativeId/accountId/planId/goalId/decisionId/budgetId/approvalId/action/initiator/status/before/after/version/requestStatus/response/verification/failure/safeRetry/idempotencyKey/history | 所有来源统一审计；前端展示嵌套响应会脱敏 |
| RiskBoundaries | accountId/dailyLimit/singleChangeLimit/approvalThreshold/minObservationMinutes/maxChangesPerDay/currency/version | 账户与资金单位独立；后端仍负责硬校验 |
| SyncStatus | source/state/syncedAt/statisticStart/statisticEnd/message | 区分加载、真实/演示、无数据、未授权、待接入、过期、失败、无权限 |

`DeliveryData` 聚合对象包含上述数组、scope、contractVersion、sync、`trends: {planId,points}[]` 和 `budgetTrends: {currency,points}[]`。

`TrendPoint` 的 actualGmvMinor/targetGmvMinor 为累计金额；日达成差额仅从连续两天的累计证据计算，日期缺口显示未知。spend/budget为当前序列口径下累计值，roi/targetRoi为当日或当前观察点的比例。forecastGmvMinor由后端预测返回，必须标注预测；前端不制造预测曲线。

跨账户/渠道ROI只在非空 comparableKey 完全一致、资金单位兼容且数据完整时允许聚合。旧快照没有可比声明，不默认合并ROI。目标实际ROI由后端按相同要求提供，不得把微信豆固定换算为人民币计算。

## 5. 新增API契约（全部待后端接入与联调）

共同约束：除只读workspace和预检外，写入需要账户授权、相应actions状态=AUTHORIZED、声明的permission与用户权限匹配、有效能力版本、真实对象归属及后端风控。mutation返回不是平台成功。

### 5.1 工作区、账户、平台能力及数据同步

`GET /v1/delivery/workspace?platform=&shopId=&accountId=&start=&end=&liveSessionId=`

返回完整 `DeliveryData`。`shops/accounts` 为当前用户可见的目录，业务数组严格按scope过滤；不应通过目录提供其他租户数据。响应source和sync.source均为API，contractVersion=delivery-v8.0。

404或未配置：保持既有API快照只读，并显著提示新增接口待接入；不转入mock。403/401：清除该范围历史业务缓存。网络失败：仅保留相同范围的历史数据并关闭写入。成功回显的范围不匹配：INVALID_RESPONSE，禁止串台。

能力状态：AUTHORIZED、UNAUTHORIZED、NOT_INTEGRATED、NOT_APPLICABLE、FORBIDDEN、ERROR。actions覆盖create/budget/bid/pause/resume/review/analyze/goal/allocate/verify/retry/rules，各项含status/reason/permission。

能力声明还需提供：execution=COMMAND_JOB/DIRECT/MANUAL；automationMode=OBSERVE/APPROVAL/CONTROLLED；refreshSeconds（null为不自动轮询）；maxAgeSeconds；schema.objectives、targets、bidEditable、minAmount/maxAmount。objectives必须是该账户真实支持值；前端不硬编码平台推广目标枚举。supportedObjects/supportedMetrics/supportedFilters/supportedColumns决定对象、可见指标、筛选和列；缺失能力不是授权。

### 5.2 新建广告计划与加热订单

`POST /v1/delivery/campaigns` / `POST /v1/delivery/promotion-orders`

请求为 `CreatePlanRequest`：accountId、platform、shopId、name、objective、target={type:PRODUCT/VIDEO/LIVE,id}、amount、可选bidMinor、start/end（带时区的ISO时间）、idempotencyKey、capabilityVersion。

ADQ的amount为CNY分，bidMinor仅在账户支持时提交；微信豆amount为整数豆且不提交ADQ出价。后端检查投放对象所有权、授权scope、素材可用状态、排期、参数范围与资金边界。

微信豆没有真实可用写接口时，actions.create必须返回NOT_INTEGRATED或NOT_APPLICABLE，execution=MANUAL。前端提供人工方案配置、JSON导出和操作指引，明确LOCAL_MANUAL_PROPOSAL，不写入订单列表、不显示平台投放成功。没有实际关联微信豆账户时要求先接入账户。

### 5.3 计划修改、预算与出价

`POST /v1/delivery/plan-changes/preview`

请求 `PlanChangeRequest`：planId、accountId、action=CHANGE_DAILY_BUDGET/CHANGE_BID/PAUSE_AD_PLAN/RESUME_AD_PLAN、newValue（CNY分或boolean）、expectedVersion、可选decisionId、idempotencyKey。

响应 `RiskPreview`：token、expiresAt、checks[{passed,message}]、requiresApproval、expectedVersion。必须有真实检查项；token绑定用户、账户、对象、旧/新配置、版本、能力版本和有效期，不能由前端自行生成通过。

`POST /v1/delivery/plan-changes`

同一请求加previewToken和platform。后端重新校验令牌绑定、当前版本、资金安全、审批需求和幂等。响应MutationResult。旧command_job执行方式则继续走旧创建→后端预检→确认→审批→执行/核验，不调用此新直连路径。

### 5.4 经营目标、拆解与调整

`POST /v1/delivery/goals` / `PATCH /v1/delivery/goals/{goalId}`

请求 `GoalRequest`：scope、name、period、start/end、gmvTargetMinor、budget、currency、roiFloor、breakdown、idempotencyKey。调整另含goalId和expectedVersion。

GMV目标为经营支付口径CNY分；预算单位明确为CNY或BEAN。breakdown中type/targetId必须对应真实实体，不允许越权关联或重复分配。后端保存完整前后版本及调整人，返回关联预算与AI策略需要重新评估的信息。现前端通过history和相关工作台展示；不得修改原企业风控规则来假装目标保存成功。

### 5.5 内部预算分配与调整申请

`POST /v1/delivery/budget-requests`

调整 `BudgetRequest`：scope、allocationId、planId|null、amount、expectedVersion、reason、可选decisionId、idempotencyKey。

新建 `NewBudgetRequest`：scope、accountId、planId|null、amount、currency、parentAllocationId|null、expectedParentVersion|null、reason、idempotencyKey。null表示请求后端创建新方案，不由前端制造正式分配ID。后端决定是否有可用的账户经营边界及上级额度。

额度检查不能只依赖前端：上级总额、未分配额、单次上限、执行冲突、审批阈值和版本都需后端事务校验。返回分配ID及approvalId，后续状态分别记录internalStatus、platformStatus和verificationStatus。

账户余额通过workspace.funds返回，独立CNY/BEAN，不返回估算汇率。平台账户资金转移不在本契约范围。

### 5.6 AI分析、证据与策略审批

`POST /v1/delivery/analyses`

请求 `AnalysisRequest`：scope、kind=GOAL_GAP/PLAN/DECISION/BUDGET/EXECUTION、objectIds、idempotencyKey。对象必须真实、可访问，并属于当前范围；无对象时前端不提交。返回分析任务ID与处理状态，完成后workspace返回AIDecision。无法分析须返回数据不足/能力未接入，不生成填充结论。

AI类型：ROI、PACING、CPA、EFFICIENCY、CREATIVE、LIVE、STATUS、SYNC。不同平台按实际指标定义，分析依据必须考虑样本、观察周期、延迟及归因窗口。

`POST /v1/delivery/decisions/{decisionId}/reviews`

请求 `DecisionReviewRequest`：decision=APPROVE/REJECT/DEFER/MODIFY、expectedVersion、comment、可选proposedValue、idempotencyKey。修订值用明确的平台原生单位，暂停/恢复的布尔策略不可按金额修订，后端必须校验动作和值类型。APPROVE仅进入后端授权审批链，不赋予前端执行权；返回approvalId/executionId供追踪。

`PUT /v1/delivery/policies`

请求 `PolicyRequest`：accountId、expectedVersion、mode、roiFloor、pacingThreshold、budgetLimit、minObservationMinutes、singleChangeLimit、maxChangesPerDay、idempotencyKey。预算上限和单次修改用账户原生最小单位。

默认OBSERVE。受控自动必须由后端单独授权；预算增加、增加消耗及关闭重要计划默认人工审批。工作模式不能授予角色、账户或平台权限。

### 5.7 执行核验和安全重试

`POST /v1/delivery/executions/{taskId}/verify`

请求expectedVersion。只查询原任务与平台回读，不重新提交预算或计划变更。返回任务/核验流程状态；由workspace刷新呈现。

`POST /v1/delivery/executions/{taskId}/safe-retry`

请求expectedVersion、原idempotencyKey。仅在后端返回safeRetry=true、任务明确FAILED、具备幂等保证时显示入口。结果UNKNOWN/VERIFYING不能重放。后端再次判断资格、版本和平台状态，前端不直接重发原平台请求。

### 5.8 通用写入响应

```ts
type MutationResult = {
  resourceId: string; state: string;
  executionId: string | null;
  approvalId: string | null;
};
```

state是后端流程状态，不能仅返回布尔success作为投放生效依据。建议新增资源和审批申请使用202；任何资金/计划写入需原生平台受理与独立回读核验，旧链仍使用CommandJob。

## 6. 执行状态与核验口径

| 标准状态 | 业务含义 | 既有command_job映射 |
|---|---|---|
| PENDING_APPROVAL | 待审批/草稿风险待确认 | DRAFT/PENDING_APPROVAL；草稿另给确认入口 |
| PENDING | 待执行 | APPROVED |
| EXECUTING | 执行中 | EXECUTING |
| VERIFYING | 待核验 | VERIFYING，或成功声明缺少回读证明 |
| EFFECTIVE | 已生效 | SUCCEEDED + PLATFORM回执 + MATCHED |
| FAILED | 执行失败 | 明确失败且不是结果未知 |
| UNKNOWN | 结果未知 | 超时或回执UNKNOWN |
| CANCELLED | 已取消/终止 | REJECTED/CANCELLED/EXPIRED，原始历史仍保留 |
| PARTIAL | 部分成功 | 新任务模型专属，不伪造旧任务为部分成功 |
| MANUAL | 待人工核查 | BLOCKED/MANUAL_REQUIRED |

新增执行模型也要求MATCHED及原生回执ID才显示EFFECTIVE，否则退回待核验。受理不等于生效，生效不等于经营效果提升。策略复盘保留采纳、执行、实际效果，不能自动宣称AI因果收益。

敏感字段token/secret/password/cookie/authorization/credential/signature/idempotency及嵌套值在前端展示脱敏。后端仍应只提供最少必要的脱敏审计字段，不能把凭证放入API业务响应。

## 7. 刷新、缓存、错误及操作冲突

- 正式环境不回退演示。旧快照仅可读取其实际统计日；其他日期保留配置但消耗/GMV/ROI显示未知。
- URL保存平台、店铺、账户、日期及业务对象ID。列表偏好和草稿按身份及范围保留于内存会话，跨工作台共享，不持久存储令牌或正式业务状态。
- 后端声明refreshSeconds后才轮询，前端最低30秒且隐藏页不发起轮询；历史报表建议null，只手动更新。直播真实安全频率须后端另行确认。
- checkedAt/syncedAt或能力超过maxAgeSeconds时阻断变更。历史数据可保留但显示过期，最近成功同步与平台对象更新时间分别显示。
- 写入期间禁重复点击和切换；成功返回后刷新投放查询与既有全局快照，关联页面重新读取。未知结果按账户锁定重复写入，仍允许核验/分析。
- 未保存编辑提供保留会话草稿、放弃、取消切换；草稿不是后端已保存的业务目标或平台计划。

| HTTP/错误 | 前端表现 | 后端协作要求 |
|---|---|---|
| 401 UNAUTHENTICATED | 会话失效，清除业务缓存，走原登录恢复 | 保留原鉴权 |
| 403 FORBIDDEN | 无权限，撤销历史缓存和动作能力 | 区分店铺、账户、功能权限 |
| 404 NO_DATA | workspace视为新契约未接入；保留旧接口只读 | 必须确认此语义；空业务用200+空数组 |
| 400/422 INVALID_INPUT | 保留输入，说明需修改 | 返回可安全展示的参数错误 |
| 409 CONFLICT | 提示版本已变化，重新同步/预览 | 不能以旧审批覆盖新配置 |
| 429 RATE_LIMITED | 遵守Retry-After，限制手动和自动请求 | 返回秒数，明确渠道级限额 |
| TIMEOUT/NETWORK_ERROR | 提交结果未知，阻止盲目重提，进入审计核验 | 按原幂等键查询真实受理状态 |
| INVALID_RESPONSE | 不接受来源、范围、版本、模型不符的数据 | 响应契约需统一；不能用Mock冒充API |

## 8. 业务联动与尚待确认事项

已建立前端真实ID链：目标拆解→计划详情；计划→AI决策；预算建议→预算安全边界/调整申请；审批/预算对象→执行任务；执行→计划效果及现有经营分析；计划关联直播与直播返回计划/诊断。目标、建议、审批、预算对象缺少后端数据时保留空态，不制造关联ID。

现有商品/素材/经营分析路由收到关联ID查询参数，保持原模块结构。其更深入的定位行为仍以各模块现有能力为准；本次不重做这些模块。

需要后端确认：

1. 哪些现有API已部署、哪些账户有实际ADQ读/写scope；工作区能力网关路径和版本。
2. 微信豆官方可用的订单读取、创建、取消、余额与效果权限；人工方案是否需要后端存档接口。
3. ADQ推广目标、层级、预算/出价字段、时段与金额约束的实际账户枚举。
4. 一个交易店铺与多个投放账户/视频号主体的业务ID映射及原始ID规则。
5. 全店支付GMV、广告归因GMV、归因窗口、退款、跨日、ROI可比key与微信豆可用转化指标。
6. 经营目标的跨账户权限模型；日/周/月/场次及父子拆解约束；目标变化如何通知预算和AI重新评估。
7. 内部预算层级/周期去重、额度占用、版本锁及账户余额接口；不得将内部预算审批当作资金调拨。
8. AI的证据格式、观察窗口、样本量、延迟、数据不足及预测字段；策略效果不做未经验证的因果归因。
9. 新审批和旧command_job的ID关联；新任务是否继续使用旧审批入口，或需要独立审批资源。
10. 核验调度、未知结果查询、原幂等键保存、安全重试资格、部分成功的子任务模型。
11. 批量变更的原子性、逐项风险预检、逐项幂等和部分失败响应。当前前端支持批量选择/预览与逐项校验，未实现未经后端支持的批量提交。
12. workspace数据规模/分页口径。目前前端对已返回集合执行筛选、排序和分页；生产大数据需后端分页和全量摘要，不能把局部分页计数当作总数。
13. 平台请求限流、安全刷新间隔、CORS/cookie部署及CSRF策略。现有响应封装是否继续沿用。
