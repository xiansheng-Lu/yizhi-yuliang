## 实现

新增`POST /v1/business-analysis/tasks`、`GET /tasks`、`GET /tasks/{id}`、`GET /results`、`GET /results/{id}`，复用Cookie/精确Origin/写CSRF。当前只接受实际查询与有界幂等键，拒绝客户端用户/租户/阶段覆盖；日期为上海自然日、最多366天，四维选择不重复。

0042在同一数据库事务提交私有分析任务和只含必要ID的Outbox；按租户/用户/幂等键串行，同键语义相同返回原task，维度顺序不影响条件摘要，换条件报冲突。真正回滚时任务与事件均不留下孤儿。普通运行角色不能直写任务状态、查询条件或结果，结果与自身任务/用户通过组合外键关联并不可修改。

当前成员需有overview.read与task.create及店铺范围；具体广告平台必须有实际账户关联与账户读取范围。受理时冻结当前可见账户集合；历史只属于当前用户，原集合失去权限时关闭读取，不把新增账户自动扩入原申请。后续计算Worker还需复核该集合与周期覆盖。

`yuliang.system.analysis_accept`在system队列使用实际prefork Worker消费，只把与原持久申请完全一致的投递记录写入PG，同事务完成Inbox。网络/数据库失败可按既有内部消息规则恢复；重复消息不生成第二任务，伪造载荷拒绝。投递确认始终不等于分析完成，GET无副作用；M4-02/M4-01b尚未交付前只保留queued/0，当前结果列表从真实数据库读取为空。
