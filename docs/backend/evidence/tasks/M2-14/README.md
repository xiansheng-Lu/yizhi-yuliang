## 后台策略批准

SERVER_POLICY只有后台方法；初始白名单为空，运行身份不能自行登记。维护配置必须绑定当前AUTOPILOT策略、已配置审批执行成员、精确账户/计划、动作、金额与百分比上限、时间窗和证明。执行成员仍需当前task.approve与双范围，且不能是申请人。后台显式白名单可以覆盖既有PC_MANUAL申请；客户端source本身不产生许可，也不开放AUTOPILOT创建或method参数。

只允许明确减预算/降低出价，或有明确“非重要”分类证据的暂停。预算上调、扩大消耗（含恢复/增加出价和未证实安全的ROI变化）、重要/未分类暂停均不能策略自动批准。SQL独立重复核对，不能仅信Python比较结果。策略批准仍用实际APPROVE风险；决定actor_kind=POLICY/method=SERVER_POLICY，审计action=approval.policy，与人工approval.manual分开，不能冒称人工批准。已批准后在EXECUTE/发送门再次复核当前审批者资格、冻结意图/策略及白名单有效性；撤销后不能借原SENT准备凭证放行。
