## 复盘

1. 散文里的"与 Worker 领取使用同一条件竞争"无法被代码验证。冻结竞争场景必须落到**同一条可执行谓词**，否则"唯一出口"只是愿望；本次把三方谓词写成 SQL 并纳入工具校验。
2. 资金安全的关键不是状态多，而是**每个不确定事实都有唯一归属出口**。把"能否释放预占/解除隔离"从状态字符串转成 E0/E1/E2 证据等级后，"超时当失败"式误释放在结构上被堵住。
3. 守卫必须在提交未知与回读未知两条路径上表现一致。否则会出现"已知在途却允许下一个写"的缺口——这类缺口在单路径看都正确，只有把两条路径并排才暴露。
4. inbox 行的存在不构成平台写资格。把"恢复调度"与"再次写平台"分开，才能让"平台写次数 ≤ 1"在全部崩溃点下成立。
5. 外部越界是**事实**不是错误。账本必须能记录真实超限值，否则同步器只能丢弃事实或把事实挡在库外；同时新增写入仍必须不越限。
6. 灰度首写最容易被"跑一次看看"绕过，因此把六阶段能力、账户×动作×金额白名单、完整受理加回读链路、5 次 MATCHED 与人工许可同时写死，且明确首写失败不降级为 Mock。
7. 跨册措辞冲突按归属卡处理：只登记与给口径，不越界改写他人分册，避免无声漂移；A22 措辞留给 R00-04 一并修订。
8. 本轮工具自检先抓出自身两处缺陷（断言把 `recoveryScheduleIsNotWriteCall` 语义写反、正则字符类漏掉数字导致判定行少解析一行），两者都是在"负例必须被拦截"的驱动下暴露的——说明故障副本机制本身有实效，不只是装饰。
