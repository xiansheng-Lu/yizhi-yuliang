## 实现与验收范围

1. 0029增加job_budget_holds与正金额budget_reservations，一申请/桶唯一，HELD同账户×内部campaign唯一（campaign已绑定provider/product/native完整上下文），运行身份只可读自己的任务记录，不能直接改R或HELD。BudgetReservations.hold是同Session原语，不自行commit；先按策略共享锁→租户预算串行锁取得本次CONFIRM实际风险结论，再由受控PG函数核对精确申请人/目标、DRAFT/期望版本/未领取未发送/有效期、同任务/版本/阶段/当前策略/当前用户/10秒窗口内非空全通过assessment。最后按稳定UUID顺序FOR UPDATE锁适用额度桶，检查真实完整当前B、R与HELD合计一致、币种/周期/覆盖/冻结和B+R+delta<=limit，通过才写R与HELD；任何后续事务参与者或审计失败整笔回滚。
2. 日预算正增量delta=max(new-old,0)，每个适用桶均预占同增量；没有增额时返回NOT_REQUIRED，不造0或负HELD。唯一企业CNY根桶必须存在；未知/未证实子桶不能靠默认额度绕过。账户分配生产者归后续预算分配卡，本卡不虚构子级额度。主企业桶就是当前已实现的上级额度，已有适用桶一并检查，旧策略/过期/缺来源/超上级额度不产生预占。固定预占键绑定原job版本与冻结hash，重复同键返回原HELD，不改变R，换键/换载荷拒绝。相同目标已有HELD或账户存在尚无定性的WRITE根请求即拒绝；HTTP200/ACK/UNKNOWN不会被当成未执行而放开。M2-11执行fence守卫尚未实现，本卡不声称已覆盖未来未接入的租约表。
3. 批准/执行前重验时，只给本申请已存在且与冻结增量一致的HELD抵扣本次重复增量；R总额继续保持，其他申请不享受抵扣。access.budget_own_hold先走当前时点精确任务权限再返回该任务/桶金额，审批人无法借它读取任意原文。风险证据记录本申请各桶抵扣金额，不能把正常version1→2→3误当新资金申请或用本申请预占抵扣其他动作。

平台响应与维护策略/全列表合同为显式合成输入，数据库及并发/权限/原子性真实运行；正常生命周期阶段用既有维护测试布置，不代表真实资金+审批+执行已接线。预占原语尚未装配到生产JobTransitions/确认HTTP；主生命周期缺省关闭，平台/付费调用均0。实际调用方须在状态/事件同事务内使用，所有资金参与者保持上述锁顺序，不能在持有job/源行锁后再反向领取租户预算锁。公开生命周期与Worker由后续卡完整装配。
