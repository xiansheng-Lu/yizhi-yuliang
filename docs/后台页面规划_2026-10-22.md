# 易致驭量后台页面规划

本次保留官网首页 `/`，重新规划后台全部 21 个业务页面，同时覆盖登录和手机端。规划目标是让运营、投手、内容制作人员和管理者按工作习惯完成任务：先找到对象，再判断状态，最后执行操作。页面名称、导航分组和布局均为本轮改版方案，现有 URL 与业务契约保持稳定。

交付范围为信息架构、逐页布局、交互规则、视觉标准和实施顺序。新增业务能力在逐页说明中标明后端依赖；结构预览中的内容仅用于评审。

## 设计方向

设计定位：面向日常运营的电商经营后台，保留易致驭量品牌蓝，采用中性底色、清楚的文字层级、适中的数据密度和固定的操作位置。

使用 TASTE skill 的改版审计、品牌保留、去模板化、文案检查与交互状态规范。该 skill 明确将密集后台、数据表格和多步表单列为非主应用范围，因此不套用营销页面的大标题、展示卡片、摄影和滚动动效要求。后台组件以 Fluent 2 的企业应用模式为统一参考；实际进入组件改造时采用官方 `@fluentui/react-components`，先做公共组件试点，再逐页迁移，不混搭第二套设计系统。

设计参数：`DESIGN_VARIANCE = 3`、`MOTION_INTENSITY = 2`、`VISUAL_DENSITY = 6`。布局稳定，动效只表达操作反馈和状态变化；列表页与表单页采用各自合适的密度。

### 现状与改版依据

| 现状 | 对使用的影响 | 规划调整 |
| --- | --- | --- |
| 四组菜单同时展开，最后一组混合经营数据和系统配置 | 常用入口难找，设置项藏在长菜单底部 | 五个业务分组，当前组展开，其他组可收起；设置位置固定 |
| 多个菜单使用 AI、工厂、作战室等称呼 | 需要先理解产品概念，才能知道在哪工作 | 用对象与动作命名，AI 能力放在具体操作处 |
| 所有页面共用英文眉题和同一句介绍 | 首屏重复，无法说明当前页用途 | 保留明确页名；只在确有必要时增加一句说明 |
| 表单、列表、生成任务都使用大圆角卡片 | 信息层级雷同，空白多，扫描距离长 | 分为概览、列表、设置、编辑、媒体制作、分析六类页面 |
| 经营目标页显示店铺、直播和平台筛选，但规则取企业级配置 | 用户容易误解规则作用范围 | 显示企业级作用范围，移除与该配置无关的筛选 |
| 投放建议、任务审批、执行记录重复展示任务列表 | 同一个任务在三页看起来没有分工 | 建议负责决策，审批负责授权，执行记录负责结果与核验 |
| 策划、脚本、视频等部分页面以三步骨架和开发说明为主体 | 无法围绕真实工作对象形成连续流程 | 先设计任务列表和对象详情，接口未接入时提供准确空状态 |
| Mock、Scope、command_job、G1-B1 等说明进入主界面 | 开发信息抢占用户视线 | 演示标识持续可见；技术细节放在环境说明或详情中 |

保留品牌名称、标志、蓝色主色、已有 URL、金额单位、任务状态含义和权限边界。官网 `public/` 文件及首页哈希基线保持不变。

## 导航与页面职责

### 一级导航

| 分组 | 页面顺序 | 使用目的 |
| --- | --- | --- |
| 经营 | 经营总览、直播监控、任务与审批、经营目标 | 看当前情况、处理待办、设置经营边界 |
| 内容 | 内容策划、脚本管理、视频制作、图片与图文、视频剪辑、素材库、素材测试 | 从需求到可使用素材 |
| 投放 | 投放计划、投放建议、预算分配、商品与货盘、执行记录 | 从投放对象到变更结果 |
| 数据 | 经营分析、复盘报告 | 分析变化并形成下一轮行动 |
| 设置 | 自动化岗位、平台连接、企业与权限 | 管理能力、账号和授权 |

桌面保留单列左侧导航，展开宽度 216px，折叠宽度 64px。一级分组可折叠，默认只展开当前组；用户手动展开的状态按用户保存。每个页面始终能从分组进入，不依赖搜索。只有实际待办才显示数量，普通菜单不加装饰圆点。折叠时图标配名称提示，设置入口保留文字或可访问名称。

内容区顶栏显示当前企业和账号菜单；页内按需提供店铺、广告账户、平台、时间和直播场次。企业切换后重新校验权限并清除不再有效的选择。只有一个可选对象时直接展示名称。新增搜索、收藏或消息中心放在后续需求中，首轮不增加空入口。

## 公共布局与操作规则

### 页面骨架

顶栏高 56px；页内标题 24px，标题下方最多一句直接说明用途。内容边距 24px，区域间距 24px，同组字段间距 16px。移除每页重复的英文眉题和营销口号；演示环境在顶栏持续显示“演示环境”，首次进入提供一次简短说明，实际变更入口继续注明“模拟”。

列表页按可用空间展开，列配置围绕当前任务选择；设置表单的编辑区域控制在 720px 左右，右侧 280px 显示作用范围或当前版本。普通单个输入框宽 240-360px，名称和描述类字段可更宽。桌面不把数字输入框铺满整行。

同一主体页面只保留一条纵向滚动链。左侧导航需要时独立滚动；表格可横向滚动但不套固定高度的纵向滚动层。媒体时间线可以横向滚动。详情抽屉作为独立层滚动，背景不跟随滚动。

### 六类页面

| 类型 | 标准结构 | 适用页面 |
| --- | --- | --- |
| 概览与监控 | 范围选择、关键指标、待处理问题、关联对象 | 经营总览、直播监控 |
| 列表与详情 | 标题和主操作、状态标签、筛选搜索、对象列表、分页 | 计划、任务、执行、建议、实验、连接 |
| 设置表单 | 分类或分组、字段、作用范围、保存栏、变更记录 | 经营目标、企业权限、岗位配置 |
| 内容编辑 | 对象列表进入、正文编辑、参考资料、版本与提交操作 | 策划、脚本、图文 |
| 媒体制作 | 项目列表进入、素材、预览、参数、进度或时间线 | 视频制作、视频剪辑 |
| 分析与报告 | 口径和时间、关键变化、趋势或证据、明细与行动 | 经营分析、复盘报告 |

短详情、简单变更使用右侧抽屉，通常宽 560-640px；长脚本、完整报告和剪辑项目进入专用详情视图。详情状态可用现有路由的查询参数表达，支持刷新、浏览器返回和深链接。关闭后保留原列表筛选、页码和滚动位置。避免在抽屉里继续叠加抽屉。

### 操作习惯

- 页面主操作位于标题右侧，如“新建策划”“上传素材”。只有真正可用的动作才显示可点击按钮。
- 行内提供最常用的一项操作，其他操作收进“更多”；表格不堆满蓝色按钮。
- 选中记录后才出现批量操作栏。首轮不提供批量批准、批量修改预算等容易掩盖对象差异的动作。
- 筛选结果即时反馈；复杂组合筛选可用“查询”和“重置”。离页再返回时恢复筛选。
- 表单保存仅在有修改且字段有效时可用；错误就地显示。网络失败保留输入，重复点击不产生重复任务。
- 普通设置一次保存即可。广告变更和权限变更在提交处展示对象、差异和影响范围，按业务要求确认。
- 未保存离开时提供“继续编辑”和“放弃修改”；支持键盘操作、清晰焦点、Escape 关闭非编辑详情并返回触发点。

## 经营页面

### 经营总览

用户首先要知道今天经营情况、哪里异常、哪些事等自己处理。

首屏依次放店铺和时间范围、广告消耗与支付 GMV 及投放 ROI、待处理事项、当前直播。指标放在一条简洁的统计带里，直接标明日期和口径；下方以异常和待审批为主，不放机器人状态大卡片。趋势图只有具备时间序列时显示，不能把单次快照画成趋势。

点击异常进入直播或计划详情；点击待办进入任务详情；经营目标只在需要调整时提供入口。自动化运行情况用“运行中、已暂停、需处理”及最近一次更新时间表达，不使用装饰性发光状态。当前具备快照与任务数据；趋势、告警和实时运行状态依赖后端。

### 直播监控

围绕一个明确直播场次工作。页首选择店铺与场次并显示开播时间、直播状态和数据更新时间；同一时刻只展示一个场次的操作对象。

首屏是场次指标、异常事件和关联投放计划。商品表现和讲品时间线放在下方标签页，证据能跳转到具体回放片段。计划变更从对应行发起，带入账号、计划和场次；通用指令入口作为辅助方式。

没有直播时显示最近场次和查看历史入口；数据过期时显示最后更新时间和重试。开播、关播沿用人工交接状态，不能显示成已直接控制直播推流。秒级数据和回放定位依赖后端与媒体服务。

### 任务与审批

专门处理谁需要确认什么、当前卡在哪一步。默认“待我处理”，另有“全部任务”和“我发起的”；标签计数只来自权限范围内的真实任务。

列表字段为动作摘要、目标对象、来源、提交时间、当前状态、处理人和操作。任务详情按“变更前后、变更理由、风险检查、审批、执行与核验记录”展开。主要按钮随状态变化，待审批任务才显示“批准”“驳回”；驳回填写原因。

批准后明确显示“已批准，未执行”。执行中不允许重复发起；失败、过期、风控阻断和待人工交接各自提供原因与可行下一步。来源字段保留 PC、手机和自动化来源。现有统一任务状态和权限可复用；服务端待办分配与正式审批通知待接入。

### 经营目标

这是企业级设置页。顶部显示“适用于当前企业的全部关联计划”，并显示当前版本、更新人和更新时间。店铺、直播间和平台筛选不控制该规则，因此不放在本页。

主编辑区分为经营目标、操作限制、工作模式。字段沿用现有契约：企业日预算上限 `budget`、经营 ROI 目标 `roi`、单次预算或出价变化上限 `change`、同计划成功操作间隔 `cooldown`、工作模式 `mode`。显示名称可以简化，提交字段名保持不变。

预算输入带“元”，ROI 显示比值并解释为经营目标；变化幅度带“%”，间隔带“分钟”。预算与 ROI 必须大于 0；变化幅度 1-100；间隔为大于等于 0 的整数，保留目前精度规则。工作模式使用单选项“人工操作”“辅助建议”“自动化候选”，每项用一句话说明，且选择模式不授予审批权限。

右侧显示作用范围和当前生效值，详细统计说明用可展开区域呈现：当前上限统计全部关联计划的配置预算，含暂停计划；它不等于实际日消耗。经营 ROI 不会自动覆盖各计划的出价或 ROI 目标。保存后提示规则版本变化及已有申请需要重新核对；API 未返回更新人和时间时不伪造。

表单下方固定在编辑区域内显示“保存修改”和“取消修改”，无需滚动整页找按钮。历史版本、影响计划数量和审计记录需要新增接口后再显示。

## 内容页面

### 内容策划

以“策划需求”为工作对象。默认表格列出标题、关联商品、渠道、负责人、计划交付日期、状态和关联脚本数量，可切换为状态看板但不作为首轮必需能力。

“新建策划”进入编辑视图，填写目标、人群、商品卖点、渠道、参考素材和交付要求。详情显示简报、讨论或修改记录、关联脚本；“创建脚本”带入简报和商品。AI 只在“生成选题建议”等明确动作里出现。空状态提供新建入口；保存和生成接口未接入时明确标注，不能展示虚构结果。

### 脚本管理

先列出脚本标题、商品、关联策划、版本、字数或预计时长、审核状态和更新人。按商品、状态和更新时间筛选。

编辑视图左侧是正文或分镜段落，右侧是简报、商品信息和参考资料；版本记录收在次级面板。正文可分别执行“改写选中段落”“补充开场”等明确动作，生成结果由用户采纳后进入正文。保存草稿、提交审核和送去制作分别表达不同结果。多人编辑冲突、版本对比和模型生成依赖后端。

### 视频制作

落地页是生产任务列表，字段为任务名称、关联脚本、规格、创建人、状态、进度和成片。新建任务依次确认脚本与素材、画幅与时长、输出要求，右侧显示当前配置摘要。

详情展示排队或生产进度、可读失败原因、成片预览和版本。完成后主操作为“加入素材库”，次操作为“继续剪辑”。轮询、取消、重试、生产耗时和下载链接均以服务返回为准；未接入生产能力时不启动假进度条。与现有 NEXORA 能力对接，不另建生成引擎。

### 图片与图文

统一管理图片和图文任务，以类型标签区分。默认结果网格使用实际缩略图，信息为标题、商品、尺寸、版本和状态；表格模式便于批量管理。

创建视图包含商品与参考图、用途与尺寸、文案要求和数量；预览与参数左右分区。图文编辑允许逐张调整图片和文案，审核通过后入库。没有图片时显示上传和创建入口，不能用大图标假充缩略图。上传、生成、审核和导出由素材服务提供。

### 视频剪辑

入口展示剪辑项目和最近编辑记录，“新建项目”后进入专用编辑器。编辑器使用素材区、预览区、属性区和底部时间线；页内导航压缩，主要空间留给素材与视频。

裁剪、字幕、配乐、画幅和导出各有明确位置。批量剪辑作为项目类型，不把所有参数一次堆给用户。导出任务在项目内可追踪，失败保留项目。复用现有 NEXORA 编辑能力；若采用外部编辑器，明确打开方式、项目返回位置和素材回收状态。

### 素材库

作为唯一素材归档入口，统一视频、图片、音频、脚本和文案的类型、版本及引用关系。顶部是搜索、类型和状态筛选、上传；可切换缩略图网格和表格。

详情显示预览、尺寸或时长、商品、版本、授权信息和使用位置。上传有逐文件进度，失败可单项重试。删除被计划或项目引用的素材时先说明影响，并以归档优先。授权信息缺失显示“授权待确认”；没有文件链接时不提供伪下载。上传存储、真实预览和引用校验待后端接入。

### 素材测试

测试对象是实验。列表包含实验名称、关联商品、对比素材、投放范围、时间、状态和当前结论。创建时先写清假设，再选择素材、评价指标、预算和观察期。

详情同时呈现对比素材和指标，标明样本量、归因窗口、消耗与时间范围。样本不足显示“继续观察”，不提前给出胜负。完成后可将结论关联到素材和投放计划。实验分流、样本充分性规则和结果计算均为新增后端依赖。

## 投放页面

### 投放计划

以店铺、平台和广告账户为范围，默认展示计划名称、状态、日预算、广告消耗、支付 GMV、投放 ROI 和最近更新时间。计划与账户层级分开，金额右对齐，数量与比值使用等宽数字。

点击计划名称打开详情，可查看参数、关联素材、变更历史和指标口径。行内“调整”打开变更抽屉，带入唯一对象并显示旧值与新值；提交后进入同一任务流程，列表先显示待审批标识，核验成功后才更新生效参数。创建平台计划为后续能力，有接口后再提供“新建计划”。

### 投放建议

只展示尚需决策的建议，按待处理、已采纳、已忽略分类。每条建议显示目标计划、建议动作、触发原因、证据时间、有效期和风险；不把预测收益画成已发生的经营结果。

详情提供指标证据与具体变化。“采纳并提交审批”创建或关联统一任务，成功后链接到该任务；“忽略”可记录原因。缺少证据、建议过期或规则版本变化时禁止直接采纳并给出重新评估入口。建议服务未接入时显示准确空状态，不能将手工创建任务伪装为 AI 建议。

### 预算分配

解决企业预算在平台、账户或店铺间如何分配。顶部展示企业日预算上限、当前已分配配置预算和可分配余额，数据口径与经营目标一致；实际消耗作为独立指标。

主体为分配表，列出分配对象、现有配额、计划配置预算、当前消耗、拟分配值和差额。修改后展示汇总是否超过企业上限，明确包含暂停计划；提交分配方案按对象生成申请或使用后端支持的批处理契约。企业上限只链接到经营目标，避免两个页面同时编辑同一个数。账户配额、预占、分配方案与批处理均需新增契约。

### 商品与货盘

页内分为商品和直播货盘。商品列表包含商品名称、店铺、价格、库存状态、关联素材与计划；缺失库存或成本时直说“未接入”。

货盘视图围绕一个直播场次展示讲解顺序、主推商品、价格与优惠信息、对应话术和素材。拖拽排序有键盘替代方式，修改后保存；商品诊断和讲品回放在对应商品详情中关联。数据来源、库存同步、优惠生效和货盘排序待后端提供，不以 Mock 值作为真实结论。

### 执行记录

展示已进入执行环节的任务及核验结果。默认字段为操作、目标、触发来源、执行时间、平台受理情况、核验结果和异常原因；筛选核验失败、超时与待人工处理。

详情用时间线分开申请、批准、提交执行、平台回执、参数回读和效果观察。平台受理不等于已核验完成；任务成功也不等于业务效果提升。可复制任务号和平台回执号，技术内容在详情展示。重试需服务明确允许，并防止重复执行；效果观察和回滚只有后端支持时才出现。

## 数据页面

### 经营分析

回答哪个平台、商品或时间段发生变化，以及是否值得进一步调查。顶部统一店铺、平台、账户、日期和对比范围；先显示广告消耗、支付 GMV、投放 ROI，再呈现趋势和贡献明细。

按平台、商品、素材、直播场次下钻，图表与明细表共享筛选和单位。用户从异常点进入相同范围的计划或场次。每个指标能查看定义、来源和更新时间；不同归因窗口的数据不直接混算。成本、退款、履约数据缺失时不显示推算利润。趋势、对比和汇总接口为新增依赖。

### 复盘报告

入口是报告列表，按日报、直播、活动或自选周期分类；显示范围、生成时间、负责人和状态。阅读页左侧为章节目录，中间是摘要、证据和行动项，右侧证据详情按需打开。

保留现有八类内容：经营摘要、平台表现、商品与直播、素材与实验、决策与执行、风险与异常、成本退款与利润、下一轮行动。缺少数据的章节说明缺项，不生成结论。证据链接返回原计划、素材、场次或任务。行动项可生成策划或操作申请；报告生成、固定版本、导出和行动关联待后端支持。

## 设置页面

### 自动化岗位

管理“哪些任务由哪个岗位处理、在什么范围内允许处理”。以岗位列表呈现岗位名称、职责、数据范围、运行状态和最近运行结果；不使用拟人头像和炫光机器人卡片。

岗位详情分为职责、规则、权限边界和运行记录。必须区分生成建议、申请审批和实际执行能力。启用前显示授权范围和审批要求；暂停后说明对已创建任务的影响。当前岗位页为骨架；调度、授权、规则、运行日志与启停由后端提供，前端开关不能冒充实际启停。

### 平台连接

以“已连接账号”为主，按平台分组列出账号名、所属店铺、授权范围、连接状态、授权到期时间和最近同步时间。未连接的平台另设可连接入口，避免所有平台都做同等大小的卡片。

主要操作为“连接账号”“重新授权”“查看权限”和“断开连接”。断开前展示受影响的计划、数据和岗位。授权状态、同步状态和接口失败分别表达；真实核验之前显示“待核验”。不在列表展示原始 token 或实现标识。授权、到期时间和连接影响分析待后端支持。

### 企业与权限

使用页内分类“企业信息、成员、角色与权限、操作日志”。各分类只展示相关内容，移除面向开发的基础状态切换器。

成员表支持邀请、角色分配和停用；角色采用明确的操作权限与数据范围。管理员能看清谁有查看、编辑、审批和执行权限。修改权限时展示变更摘要并检查当前操作者权限；没有权限的用户可见说明及联系管理员方式。成员邀请、角色持久化、服务端校验与审计查询待后端接入。

## 登录与手机端

### 登录

`/login` 使用紧凑品牌区和单列表单，标题为“登录工作台”，主按钮为“登录”。保留账号标签、密码可见切换、自动填充和错误提示。演示环境显示“使用演示账号”，正式环境不显示演示账号或 API 术语。

登录成功返回用户原来要访问的合法页面；保留现有 next 白名单。验证码、企业单点登录和找回密码仅在后端支持后加入，不能提供无效链接。

### 手机端

`/mobile` 保持四个入口，但改成底部导航“指令、直播、任务、复盘”。每次进入优先显示当前标签内容，移除所有标签上方重复的大标题、全量指标和长筛选表单。

页顶以一行显示企业、店铺与当前场次，点击后展开范围选择。指令页保留最近对话和少量常用操作；解析后必须显示对象和变更前后，再提交审批。直播页优先显示场次和异常；任务页保留待处理状态和任务详情，正式手机审批需有相同服务端权限支持；复盘页先摘要，再看证据。

复杂编辑移到 PC；手机仍可查看结果与任务状态。移动端最小触控区域约 44px，正文 14-16px，输入框 16px，表格改为关键字段列表。窄屏详情使用整页，底部操作避开系统安全区。

Mock 模式始终说明同源同浏览器共享，不宣称跨设备同步。真实两端同步、推送、审批和账号权限均依赖后端会话与任务服务。

## 数据口径与交互状态

企业配置、分析筛选和编辑对象是三种不同范围。企业日预算上限作用于企业；分析指标使用已选择范围；广告变更必须锁定唯一计划。跨页面跳转携带合法范围，修改店铺时重置不适用的账户与场次。

预算和出价在界面显示元，提交继续使用 CNY 整数分。ROI 使用独立比值字段，不当作货币或出价。消耗为零时 ROI 显示“暂无数据”，不显示无穷大；缺失数据不替换为 0；暂停计划的历史消耗继续参与所属日期统计。

任务状态沿用 `DRAFT`、`PENDING_APPROVAL`、`APPROVED`、`EXECUTING`、`VERIFYING`、`SUCCEEDED`、`FAILED`、`REJECTED`、`CANCELLED`、`EXPIRED`、`BLOCKED`、`MANUAL_REQUIRED`。前端可以优化展示文案，但不合并批准、受理和核验成功。旧申请遇到规则变化必须重新核对，不能自动继承批准结果。

| 状态 | 页面表现 | 后续动作 |
| --- | --- | --- |
| 首次无对象 | 解释当前对象是什么，给出有权限的新建或连接入口 | 创建、上传或连接 |
| 筛选无结果 | 保留筛选与表头，说明当前条件无匹配 | 清除条件 |
| 加载中 | 使用与最终内容同形的骨架，保留范围选择 | 等待当前区域加载 |
| 局部失败 | 错误贴近失败区域，已成功内容保持可见 | 重试该区域 |
| 无权限 | 说明所需权限，保留可见上下文 | 联系管理员或返回 |
| 未接入能力 | 说明需要连接的数据或服务，入口仅指向真实可用动作 | 平台连接或能力说明 |
| 数据过期 | 显示最后更新时间，旧数据仍可辨认 | 刷新，阻止依赖新数据的变更 |
| 保存失败 | 保留输入，显示字段或服务错误 | 修正或重试 |
| 并发冲突 | 展示服务端最新版本与本地修改 | 重新核对后提交 |

## 实施顺序与验收

### 公共骨架与最常用流程

先建立后台独立的导航、标题、筛选、表格、详情和表单组件。以经营目标、投放计划、任务与审批作为三个试点页；验证输入、返回列表和任务状态后，再迁移总览与直播监控。官网样式和静态资源隔离，试点通过后继续覆盖全部页面。

### 内容生产流程

依次建立策划、脚本、素材库，再接入视频、图文与剪辑，最后增加素材实验。先保证对象能保存、能返回、能找到引用关系，再接入生成服务。当前骨架页面不能仅换皮后标记为业务完成。

### 投放与复盘流程

对齐投放建议、预算分配与执行记录的实体和接口；补齐趋势、归因、报告与证据跳转。岗位、连接、权限按各自后端能力同步落地。

### 验收标准

- 21 个业务路由各有明确职责、主内容和下一步，旧路径可以直接访问。
- 1366×768 桌面首屏能辨认当前页、作用范围和主要操作；经营目标无需左右扫视超长输入框。
- 经营目标保存、计划变更申请、任务审批、核验结果查看能完整走通，批准与成功显示正确。
- 策划、脚本、成片和素材之间的跳转带入正确对象；返回列表保留筛选与位置。
- 列表及表单具备无数据、无匹配、加载、失败、无权限和并发变化处理。
- 1920、1440、1366、1024、768、390、320px 进行响应布局检查；只有必要表格或时间线允许横向滚动。
- 正文对比度至少 4.5:1；交互边界和焦点可辨；全流程键盘可用；状态不只靠颜色。
- 演示数据与未接入能力标记准确，不把 Mock 操作、预测结果或平台受理当作真实成功。
- 官网首页哈希与既有基线一致；本轮规划不会改动首页源文件。

以上是后续实现的验收要求，不代表当前全部业务能力已完成。
