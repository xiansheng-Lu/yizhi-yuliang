三条DoD：创建/确认/批准/执行前均做适用且有依据的非空检查；策略版本/时间落申请与审计，不能复用旧结论；失败不能被审批/AI覆盖，越范围错误无对象泄露。

## 三条DoD与实际实现

1. 创建入口已直接使用RiskFramework；确认、批准、执行前提供assess_job三个服务端校验入口。各入口重新核对当前身份/范围、阶段/有效期、原申请人动作权限、六阶段WRITE能力、当前授权/确认页新鲜度与现值。批准入口按真实审批人的范围访问该任务，同时核对原申请人的权限，不能用审批人权限掩盖申请人撤权。超过范围只返回通用403/404，不返回对象/配置细节。
2. 0025增加受控risk_policies与只追加policy_versions；维护身份按期望版本与证明更新，运行身份不能自行提额。共享/独占策略锁保证一次事务所用版本稳定，普通风险结果不作为下一时点的输入。每次生成新assessment ID与数据库时钟，关联原任务/版本/阶段，保存SERVER非空checks及安全证明引用，独立追加risk.assess审计。创建评估与任务同事务，任务FK延迟到提交校验，失败不能留下孤儿风险记录。10秒检查窗口独立于数据两时间，不拿checked_at冒充来源时间。
3. 已知的授权过期、数据过旧、能力撤销、现值改变、原申请人撤权、策略换版分别产生实际失败检查；已有审批或任何AI结果不能改成通过。创建请求仍不接受客户端risk/old_value等服务端事实。风险历史按实际检查者私有RLS保护，审计失败整笔回滚。缺任何必需规则实现都会显式BLOCKED，不能只凭配置存在或代码目录存在给REVIEW_REQUIRED。

PolicyConfig需要显式CNY整数分上限、ROI、幅度、冷却、日次数与模式，无生产额度默认值；BEAN/USD、非整数/越界/NaN和额外凭据字段均拒绝。当前仅实现版本/检查框架，额度/幅度/频率规则归M2-09a，批准意图绑定归09b，资金/执行/审批参与者归后续卡。注册表缺AMOUNT_LIMIT/CHANGE_BOUND/FREQUENCY/INTENT_BINDING时，每项都保留失败依据，POLICY_ENGINE_READY=false。本卡未注入全通过测试规则，也没有生产策略配置或执行放行。

## 实际验证与边界

14项专用集成使用真实PG：四入口检查与关联审计、重复调用新ID/新时间、策略换版、授权/数据/现值/能力/申请人变更、范围/租户拒绝、运行身份不可改策略或检查历史、风险审计回滚及审批人私有记录。创建入口复核现值两次并保存来源证明；账户共享锁按连接冻结的既有顺序先于源锁取得，避免后续评估与断开互相等待。另14项策略配置规则测试验证单位/数值/额外字段边界。

供应商授权与确认页仍为既有合成测试端口；确认/批准/执行前的初始任务状态由维护身份显式布置，只用于核验本时点检查，不能称此前实际规则/审批/资金流程已完成。trace.json记录一个真实本地EXECUTE评估及其安全引用，明确SYNTHETIC_PRECONDITIONS_ONLY和实际0平台/付费调用。全量命令、数量与迁移结果见verification.json。

RiskFramework提供同Session入口供后续参与者调用，不把其接成未完成的确认/审批/执行生产参与者；现有JobTransitions缺省关闭不变，没有新增公开任务写路由或活跃Worker。本卡不创建资金预占、执行attempt、平台回执或人工签字；F06/F07浏览器联调和BE/FE复核待完成，G0/E08保留。

回退停用风险入口，保留策略版本、关联检查、原申请与来源证据；禁止覆盖旧策略或删除失败检查使申请放行。继续M2-09a补齐确定性规则，再逐卡实现意图/额度/审批/执行，不以框架通过代替完整闭环验收。
