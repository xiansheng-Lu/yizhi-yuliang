# 14 接口契约详设（Schema、错误码与 SSE 帧）

R00新增项与黄金样例见[冻结决定](../contracts/冻结决定.md)。GET /v1/auth/csrf和独立素材上传任务路径均标记待F01/F11复核；现有请求无新增不兼容必填字段。

本册是 05 册的下一级细化：给出关键接口的请求/响应 JSON 结构、全量错误码表、HTTP 头约定与 SSE 事件帧格式。目标是后端开发可以直接照此写 Pydantic 模型，前端联调时以本册为字段级依据。通用信封、HTTP 状态语义、路径总表仍以 05 册为准。

## 1. 全量错误码表

错误信封：`{requestId, error:{code, message, details[], retryable}}`。message 为可直接展示的简体中文；details 用于字段级问题；retryable 仅在客户端可以原样重试（或退避重试）时为 true，资金类写动作永远 false。

| code | HTTP | retryable | 触发场景与 details 约定 |
|---|---|---|---|
| INVALID_INPUT | 400/422 | 否 | Pydantic/业务校验失败；details:[{field,reason}]；金额非法、ROI 非正、枚举未知 |
| UNAUTHENTICATED | 401 | 否 | 无会话、会话过期或已吊销 |
| FORBIDDEN | 403 | 否 | 无动作权限，或对象不在数据范围 |
| NO_DATA | 404 | 否 | 资源不存在；V9 未接入能力也可用 404 表达（与空集合 200+[] 区分） |
| VERSION_CONFLICT | 409 | 否 | expectedVersion/expected_version 不符；details 带 current 资源快照 |
| ILLEGAL_TRANSITION | 409 | 否 | 当前状态不接受该生命周期动作；details:{from,event} |
| IDEMPOTENCY_MISMATCH | 409 | 否 | 幂等键已绑定不同载荷（request_hash 不一致） |
| POLICY_VERSION_CHANGED | 409 | 否 | 等待审批期间风控策略升级，需重新确认 |
| TARGET_QUARANTINED | 409 | 否 | 目标存在 UNKNOWN 在途，守卫隔离中 |
| RESOURCE_TERMINAL | 409 | 否 | 终态对象再次操作 |
| RISK_BLOCKED | 422 | 否 | 风控 BLOCKED；details 带未通过的 checks |
| MANUAL_ONLY | 422 | 否 | 该动作只支持人工交接（如无授权开播关播） |
| CAPABILITY_UNAVAILABLE | 422 | 否 | 六阶段能力未全 PASS、scope 不足或能力已降级；details:{phase,availability} |
| VALIDATION_TOKEN_INVALID | 422 | 否 | 创编一次性校验令牌过期或绑定配置被篡改 |
| DATA_COVERAGE_INSUFFICIENT | 422 | 否 | 报告周期数据覆盖不足（日报 1 天/周报连续 7 天/月报完整自然月）；details 标注缺口 |
| LOCKED | 423 | 否 | 结果未知期间重复提交被锁定，引导查询/对账 |
| RATE_LIMITED | 429 | 是 | 限流；响应头 Retry-After |
| PLATFORM_REJECTED | 502 | 否 | 平台明确拒绝；details:{platformCode,category}，资金类不可自动重试 |
| UPSTREAM_ERROR | 502 | 视分类 | 平台 5xx/网络异常；写动作按结果未知处理，retryable=false |
| UPSTREAM_RATE_LIMITED | 502 | 是 | 平台侧限流，连接器退避；不占用户重试次数 |
| RESULT_UNKNOWN | 504 | 否 | 写动作结果未知；任务维持进行中投影，进入对账（不代表最终失败） |
| AI_UNAVAILABLE | 503 | 是 | LLM 网关主备模型均不可用；查询类功能不受影响 |
| PROVIDER_PENDING | 503 | 否 | 生成供应商已受理但结果未明（任务状态查询，不是报错重试入口） |
| INTERNAL_ERROR | 500 | 否 | 兜底；不向前端返回堆栈，requestId 用于排查 |

未在表中的 HTTP 5xx 一律不触发前端自动重放写请求。平台错误码到本表的分类在连接器内完成（见 07 册），业务接口只输出统一码。

## 2. 通用结构

### 2.1 分页

请求：`?cursor=<opaque>&limit=50`（默认 50，上限 100）。

```json
{
  "items": [],
  "nextCursor": "eyJ0IjoiMjAyNi0xMC0yNlQwOjAwWiJ9",
  "truncated": false
}
```

游标为不透明 base64，内含排序键与实体 id；新增列表默认按 created_at/id 稳定排序。truncated=true 表示因服务端保护上限截断（快照接口同此约定）。

### 2.2 关键请求/响应头

| 头 | 方向 | 约定 |
|---|---|---|
| X-CSRF-Token | 请求 | 写请求必带（双重提交，见 09 册） |
| Idempotency-Key 或体字段 idempotencyKey/Idempotency-Key | 请求 | 创建类必带；按各契约的既有位置，不强行统一 |
| If-Match: <version> 或体字段 expectedVersion | 请求 | 更新类；字段位置跟随各契约 |
| X-Request-Id | 响应 | 与信封 requestId 一致 |
| Retry-After | 响应 | 429/UPSTREAM_RATE_LIMITED 时给秒数 |
| Last-Event-ID | 请求 | SSE 断线续传 |

## 3. 认证与身份

POST `/v1/auth/login`（两种 body）：

```json
{ "email": "ops@example.com", "password": "********" }
```
```json
{ "email": "ops@example.com", "code": "492716", "challengeId": "8f1c...", "method": "email_code" }
```

成功 data（Identity 字段沿用前端 domain 定义）：

```json
{
  "userId": "u_...",
  "displayName": "张投手",
  "email": "ops@example.com",
  "tenantId": "17",
  "shopIds": ["s_001", "s_002"],
  "permissions": ["snapshot.read", "task.create", "plan.write", "content.write"],
  "workspacePages": ["command", "overview", "monitor", "plans", "planning", "reports"],
  "mode": "API"
}
```

规则：`mode` 只输出 "API"；permissions 为权限点扁平数组，workspacePages 由权限点推导（同一真相），每项必须属于 `src/lib/routes.ts` 的 customerPageIds，不能返回概念分组名 delivery/live/content/reporting。示例仅展示合法页面值，实际集合须从完整角色权限推导。邮箱未注册与密码错误统一返回 UNAUTHENTICATED 与相同模糊文案。Set-Cookie 为不透明会话 id（HttpOnly、Secure、SameSite=Lax）。

POST `/v1/auth/email-codes`：

```json
// 响应
{ "challengeId": "8f1c...", "expiresAt": "2026-10-26T10:15:00+08:00", "retryAfterSeconds": 60 }
```

触发节流时 429 + Retry-After，不泄露邮箱是否已注册。

## 4. 快照

GET `/v1/frontend/snapshot`：data 为前端 FrontendSnapshot 全量结构；以下为可进入 G0 空工作区的完整最小形状：

```json
{
  "schemaVersion": "command-job-v1.0",
  "revision": 1,
  "source": "API",
  "tenants": [], "shops": [], "adAccounts": [], "liveSessions": [],
  "plans": [], "products": [], "materials": [], "tasks": [],
  "riskPolicies": [], "replaySegments": [], "replayReports": [], "connectors": [],
  "scope": { "shop_id": "all", "live_session_id": "all", "connector_id": "all", "date": "2026-10-26", "timezone": "Asia/Shanghai" }
}
```

- 当前客户端强校验集合为数组，不能改为 items 对象；快照不允许静默截断。超规模按 05 册先联合升级分页和概况接线，再扩大开放范围。
- `source` 字段固定 "API"；connectors 元素保持前端 Connector 结构（id/status/scopes/checkedAt）。

PUT `/v1/frontend/reporting-scope`：body 为 ReportingScope（shop_id/live_session_id/connector_id/date/timezone），date=YYYY-MM-DD 按 Asia/Shanghai。

## 5. 指令任务（command_job V1.0，蛇形字段）

### 5.1 创建 POST `/v1/command-jobs`

```json
{
  "source": "MOBILE_COMMAND",
  "shop_id": "s_001",
  "target_type": "AD_PLAN",
  "target_id": "20241_abc",
  "action_type": "CHANGE_DAILY_BUDGET",
  "new_value": { "kind": "MONEY", "currency": "CNY", "amount_minor": 500000 },
  "intent": "今晚大促把日预算提到五千",
  "idempotency_key": "b3f1-..."
}
```

服务端补 old_value（回读平台现值），执行创建时全量风控，返回完整 CommandJob（status=DRAFT 或 BLOCKED/MANUAL_REQUIRED）。校验规则与前端 validateJobValue 完全一致：

- MONEY：CNY、整数分、>0 且 <=2^53-1；
- RATIO：有限数、>0；
- BOOLEAN：RESUME 必须 true，PAUSE 必须 false；
- HANDOFF：START/END 与动作对应。
- source=AUTOPILOT 的外部请求一律 400 INVALID_INPUT。

### 5.2 生命周期动作

| 接口 | body | 说明 |
|---|---|---|
| POST `/v1/command-jobs/{id}/confirm` | `{job_id,expected_version}` | DRAFT→PENDING_APPROVAL；策略过期 409 POLICY_VERSION_CHANGED |
| POST `/v1/command-jobs/{id}/approvals` | `{job_id,decision:"APPROVE"\|"REJECT",expected_version}` | 当前 V1 客户端不传 comment；不能以缺少 comment 拒绝既有合法请求；如需必填意见须联合升级 UI/类型 |
| POST `/v1/command-jobs/{id}/cancel` | `{job_id,expected_version}` | job_id 须与路径一致；已领取 409 ILLEGAL_TRANSITION |
| POST `/v1/command-jobs/{id}/safe-retry` | `{idempotency_key}` | 仅 FAILED+可重试+白名单；新 attempt 不新建单 |

### 5.3 查询

- GET `/v1/command-jobs?cursor=&limit=&status=`：分页列表。
- GET `/v1/command-jobs/{id}`：完整 CommandJob（含 risk_summary/approval/execution_receipt/history）。
- GET `/v1/command-jobs/{id}/attempts`：

```json
{
  "items": [
    {
      "attemptNo": 1,
      "status": "UNKNOWN",
      "platformRequestKey": "tx-...",
      "receipt": {
        "source": "PLATFORM",
        "platformReceiptId": null,
        "accepted": null,
        "receivedAt": null,
        "verification": "UNKNOWN",
        "observedValue": null,
        "verifiedAt": null
      },
      "startedAt": "2026-10-26T20:01:11+08:00",
      "finishedAt": null,
      "verifications": [
        { "at": "2026-10-26T20:03:00+08:00", "result": "UNKNOWN" },
        { "at": "2026-10-26T20:05:00+08:00", "result": "UNKNOWN" }
      ]
    }
  ]
}
```

attempts 接口需要单独的"任务查看/核对"权限点；只提供核对依据，不提供人工改成功的操作。

UNKNOWN 投影（见 12 册 2.4）：提交是否受理未知时 status=EXECUTING、accepted=null；已有 accepted=true 证据而回读未知时保持 VERIFYING，不清除受理事实。两者均 verification=UNKNOWN，error={code:"RESULT_UNKNOWN",message:"已提交，平台结果核对中，请稍后查看",retryable:false,at}。V8 同时投影为 UNKNOWN，前端适配见 19 册 F06。

## 6. 投放管理（V8，驼峰字段）

POST `/v1/delivery/plan-changes/preview`：

```json
{
  "planId": "p_001",
  "accountId": "a_001",
  "action": "CHANGE_DAILY_BUDGET",
  "newValue": 500000,
  "expectedVersion": 3,
  "idempotencyKey": "b3f1-..."
}
```

响应 data 为 `RiskPreview`：`{token,expiresAt,checks:[{passed,message}],requiresApproval,expectedVersion}`。风控检查有真实依据，非空；需要补充 B/R/limit 明细时作为兼容字段另行冻结。preview 不推进执行状态、不写预占；可持久化短期预检票据与审计。

POST `/v1/delivery/plan-changes`：同结构加 `previewToken` 和 `platform`，返回 `{resourceId,state,executionId,approvalId}`。没有 `/submit` 后缀；newValue 按动作是整数分或布尔，字段来自 `PlanChangeRequest`。服务端回读现值，提交送审的增额预占在短事务内完成；受理不等于平台成功。

funds 四口径（可用余额/在途/未结算/授信）字段名沿用 V8，微信小店结算、广告钱包、微信豆三个接口分组返回，前端不混算。

## 7. 创编配置（V9）

| 接口 | 要点 |
|---|---|
| GET `/v1/delivery/configuration/catalog` | 产品线/步骤/字段目录，字段带六态之一（PUBLIC/AVAILABLE/API_PENDING/AUTH_REQUIRED/NOT_APPLICABLE/UNCONFIRMED） |
| GET `/v1/delivery/configuration/options?cursor=` | 标签/人群/版位等选项分页 LookupPage，不一次性全量 |
| POST `/v1/delivery/configuration/validations` | 提交完整配置，返回一次性 validationToken（短时有效，绑定配置哈希） |
| POST `/v1/delivery/configuration/tasks` | body 必须带 validationToken；服务端校验令牌与配置哈希一致才建任务 |
| GET `/v1/delivery/configuration/tasks?product=&accountId=&idempotencyKey=` | 当前客户端按原幂等键查询任务；按 id 查询如新增不能替代此入口 |
| POST `/v1/delivery/configuration/tasks/{id}/cancellations` | 携带原创建键+新撤回键 |
| GET `/v1/delivery/integrations/context` | entity/account/shop/objective/target 上下文与 links 多对多 |
| POST `/v1/delivery/integrations/commands` | 向导内动作命令，全部进执行内核，无旁路 |

    "code": "CAPABILITY_UNAVAILABLE",

## 8. 内容域（驼峰，对齐 content-factory.ts）

文档云端保存：

| 接口 | 说明 |
|---|---|
| GET `/v1/content/documents?kind=&productId=&cursor=` | 列表（planning 页同时返回 kind=scripts，同前端 contentDocumentMatchesPage 规则） |
| GET `/v1/content/documents/{id}` | 完整文档（含 brief/body/scenes/boards/nodes/edges/clips/settings/messages） |
| PUT `/v1/content/documents/{id}` | body为完整ContentDocument，`version`作期望云文档版本；映射DB revision列；冲突409带服务端文档。ContentState.revision是本地容器版本，不能用作单文档锁 |
| POST `/v1/content/documents/{id}/flow` | body `{kind:"scripts"\|"videos"\|"graphics"\|"editing"}`，服务端按前端 flowDocument 规则派生子文档（复制 brief/继承 settings、生成默认节点/画板），返回新文档 |
| POST `/v1/content/documents/{id}/review` | draft→review |

生成：

```json
POST /v1/content/generation-jobs
{
  "documentId": "d_...",
  "type": "VIDEO",
  "parameters": { "ratio": "9:16", "duration": 15, "scenes": [] },
  "estimatedCostConfirm": true,
  "idempotencyKey": "g_..."
}
```

响应与轮询返回：

```json
{
  "id": "gj_...",
  "status": "WAITING_PROVIDER",
  "progress": 0,
  "externalJobId": "nx_...",
  "cancelSupported": false,
  "estimatedCostMinor": 1200,
  "actualCostMinor": null,
  "error": null,
  "resultAsset": null
}
```

WAITING_PROVIDER 期间前端查询同一单。发送前先持久化供应商请求键/尝试状态，不能仅依赖返回后才得到的 external_job_id 唯一约束防止二次付费；供应商不支持查单/去重时挂起人工核对。SUCCEEDED 时 resultAsset 给素材 id 与预签名下载 URL。素材与账户关联：

- POST `/v1/content/account-links` 仅登记"交接意图"（结构同前端 ContentAccountLink），不是平台上传回执；
- 实际上传到平台走连接器写链路（执行内核 + 回读 + 素材审核状态），两段链路在 UI 上明确区分。

## 9. SSE 事件帧

GET `/v1/events`，响应 `text/event-stream`。事件来自 event_projections，帧格式：

```text
id: 17:1048577
event: job.changed
data: {"tenantId":"17","entityType":"command_job","entityId":"cj_...","version":7,"changes":{"status":"VERIFYING"},"at":"2026-10-26T20:02:40+08:00"}

```

约定：

1. `id`为租户绑定游标（示意tenantId:tenant_seq），按租户提交可见顺序递增，不能使用全局identity id推断提交顺序。断线重连携Last-Event-ID，校验当前租户与范围后补发；保留7天，过旧发resync。序号分配与投影同事务、持租户水位行锁到提交，避免低序号晚提交被跳过；结构见13册。客户端首次重连的游标传递方式属于F12，不能假设现有subscribe已实现。
2. data 只含"谁变了、版本号、变化字段摘要"，不含完整业务对象；客户端去重、防乱序、合并短时间重复刷新后，带权限重新 GET 资源。
3. 事件类型（下划线或点分，固定集合）：

| event | 触发 | 客户端动作 |
|---|---|---|
| job.changed | command_job 状态/版本变化 | 重拉任务（列表/详情按可见性） |
| approval.changed | 审批状态变化 | 更新待办与任务详情 |
| execution.unknown | 进入 UNKNOWN/对账 | 展示核对中标识，不弹失败 |
| capability.changed | 连接器能力降级/恢复 | 刷新 connectors 与字段可填态 |
| sync.completed | 同步批次完成（workspace 范围） | 按范围刷新概况/计划 |
| generation.changed | 生成任务状态变化 | 更新生成进度或拉取结果 |
| analysis.changed | 分析/报告任务变化 | 更新任务行 |
| resync | 游标过旧/权限变化 | 全量重读 |

4. 连接建立与每次补发都校验会话与数据范围；用户被吊销会话或跨租户切换后服务端主动关闭流。
5. 心跳：每 25 秒一帧 `: ping` 注释行；代理层（Nginx）关闭缓冲（`X-Accel-Buffering: no`）。
6. 429/5xx 与连接中断：客户端指数退避重连（上限 30 秒），期间不重放任何写请求，超过阈值回退到既有轮询节奏。

## 10. 模型组织

- Pydantic 输出模型按契约分组：`schemas_command_v1.py`（蛇形，alias 序列化）、`schemas_delivery_v8.py`、`schemas_configuration_v9.py`、`schemas_content_v1.py`；内部 ORM 模型命名规范统一，在接口层用 adapter 转换。
- JobValue、RiskSummary、JobReceipt、JobApproval 的字段与枚举必须逐项等于前端 `command-job.ts`，在契约黄金样例测试中锁定。
- schemaVersion 仅载荷真实变化时升版；信封层不随业务字段小改而升版。
