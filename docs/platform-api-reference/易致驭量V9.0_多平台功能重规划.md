# 易致·驭量 V9.0｜基于四份开放平台接口图谱的多平台功能重规划

**规划基准**：用户提供的《腾讯营销开放平台API接口全景看板》《巨量引擎开放平台API接口全景看板》《微信小店API全量接口图谱》《小红书开放平台API接口全景看板》。整理日期：2026-10-23。  
**边界**：这四份是接口目录与路径资料，**不构成已取得应用 scope、账户授权、灰度白名单或已联调成功的证明**。产品设计与接口落地应逐项核验。

## 1. 核心结论

1. 保留驭量现有左侧一级架构和五个投放管理工作台，升级为平台能力驱动，不为每个平台复制整套系统。
2. **广告投放执行产品**：腾讯营销 ADQ、巨量引擎（巨量营销 / 千川 / DOU+ / 本地推依据具体账户和产品线拆分）、小红书聚光；视频号微信豆加热作为单独待核验的产品线。
3. **经营数据与商品资产**：微信小店并非广告平台；作为店铺经营、订单归因核验、商品货盘、直播数据来源，与ADQ账户和视频号建立授权关联。
4. 新建投放流程按 **平台→产品线→账户→目标→投放对象→定向→预算与出价→素材→核验与提交** 动态编排。
5. “接口目录可见”“请求路径已核验”“应用取得scope”“具体账户授权”“参数规则校验通过”“真实写入及回读核验成功”必须是六个不同状态，不得合并。

## 3. 产品信息架构

### 3.1 保持左侧导航

- AI驭量中枢：经营异常、跨平台待办、AI策略、审批任务，不做泛用聊天机器人。
- 经营概况：三大核心KPI（今日广告消耗、支付GMV、投放ROI），下方按业务和平台拆分趋势与经营健康度。
- 直播运营：直播间列表、单场大屏、场次详情、直播效果联动、关联投放和商品。
- 投放管理：经营目标 / 计划中心 / AI投放决策 / 预算调度 / 执行记录。
- 内容工厂：素材资产、创意制作、适配审核、投放关联、效果回流。
- 数据复盘：多平台归因差异、计划/素材/商品表现、策略效果、日报周报。
- 商品与货盘（如项目中已有该模块，则原位增强）：商品库、库存、商品经营、营销券、达人分销及关联计划。

### 3.2 全局上下文

- 经营主体 / 店铺：微信小店、其他已授权经营主体；不要把微信小店和广告投放渠道当作同一级。
- 投放平台：腾讯营销、巨量引擎、小红书聚光、微信豆加热（单独待接入）。
- 产品线：腾讯营销按支持的营销目标和类型；巨量区分巨量营销、千川、DOU+、本地推；聚光区分标准投、搜索、简单投；微信豆区分直播/短视频。
- 投放账户：授权及权限；店铺/直播间/商品：业务对象；时间范围与数据同步状态。
- 全平台模式默认汇总和分析，不提供假定通用的新建广告表单。

## 4. 平台级功能规划（按真实接口目录）

### 4.1 腾讯营销 ADQ

**创建与控制**：`adgroups/get`、`adgroups/add`、`adgroups/update`、`adgroups/update_daily_budget`、`adgroups/update_bid_amount`、`adgroups/update_configured_status`、`adgroups/update_datetime`；`dynamic_creatives/add`、`dynamic_creatives/update`、`dynamic_creatives/get`。

**完整创建向导**：账户/资质→选择实际营销目标/可投内容→版位/场景→人群→预算出价排期→广告创意与审核→预览校验→提交→回读。

**人群工作区**：基本性别、年龄、地域，兴趣/行为标签、定向模板、自定义人群、排除人群、可用扩量项，全部通过能力表决定；真实标签来自 `targeting_tags/get`、`scene_spec_tags/get`；人群来自 `custom_audiences/get`、`targetings/get`；估算接口 `estimation/get`、`targeting_tags_uv/get`、`custom_audience_estimations/get`。不将所有字段默认为通用必选。

**资产/直播/微信小店**：`wechat_channels_accounts/get`、`wechat_shop/get`、`wechat_store_product_items/get`、`videos/get`、`videos/add`、`marketing_target_assets/get`。

**数据/核验**：`daily_reports/get`、`hourly_reports/get`、`funds/get`、`realtime_cost/get`、`operation_log_list/get`；`optimization_goal_permissions/get` 作为优化目标权限核查。

### 4.2 巨量引擎

**先选产品线，不允许将千川/本地推/DOU+混成普通营销单元。**

- 巨量营销项目/单元：`/project/list/`、`/project/create/`、`/project/update/`、`/project/status/update/`、`/promotion/list/`、`/promotion/create/`、`/promotion/update/`、`/promotion/bid/update/`、`/promotion/budget/update/`。
- 定向/人群：`/audience_package/get/`、`/audience_package/create/`、`/dmp/custom_audience/select/`、`/tools/interest_action/interest/category/`、`/tools/interest_action/action/category/` 等。
- 素材：`/file/video/ad/`、`/file/video/get/`、`/file/material/list/`、`/file/preaudit/submit/`、`/oc_project/material/create/`。
- 预算与出价：`/advertiser/budget/get/`、`/advertiser/update/budget/`、`/advertiser/fund/get/`、`/tools/bid/suggest/` 等；资金转移单独审批。
- 诊断/起量：`/tools/diagnosis/ad/get/`、`/tools/diagnosis/suggestion/get/`、`/tools/promotion_raise/set/`、`/tools/material_raise/create/`，须确认适用版本。

- DOU+：`/douplus/optional_items/list/`、`/douplus/optional_targets/list/`、`/douplus/order/create/`、`/douplus/order/list/`、`/douplus/order/report/`、`/douplus/order/close/`。该产品线用订单式创建流程，不复用项目/单元向导。
- 千川/本地推：必须由服务端能力响应识别对应产品线及许可，不能仅凭接口目录中的其它产品线接口推断已支持。

### 4.3 小红书聚光

**已经列出并带路径的能力**：`/jg/campaign/list`、`/jg/campaign/update`、`/jg/campaign/status/update`、`/jg/unit/list`、`/jg/unit/update`、`/jg/creativity/search`、`/jg/creativity/update`、`/jg/target/get_available_target_info`、`/jg/crowd/estimate`、`/jg/data/report/realtime/campaign`、`/jg/data/report/offline/campaign`、`/jg/note/list`、`/jg/account/budget/update`（详情和授权仍需实测）。

**功能**：计划、单元、创意分级表格；搜索关键词/否定词工作区；笔记与落地页资产；实时/离线报表；账户预算与流水；定向选择与覆盖人数估算。

**限制**：图谱中的“新创编API”“简单投新建”“创建广告组”“创建定向包”等接口路径未核验，不得将按钮做成真正写入。先实现表单草稿/接口契约/可用性提示，待确认创建方法、参数、授权之后解锁。

### 4.4 微信小店：电商经营数据中心

- 经营概况：`/channels/ec/compass/shop/overall/get`、`/channels/ec/compass/shop/live/list/get`、`/channels/ec/compass/shop/product/data/get`、`/channels/ec/compass/shop/sale/profile/data/get`。
- 商品货盘：`/channels/ec/product/list/get`、`/channels/ec/product/get`、`/channels/ec/product/stock/get`、`/channels/ec/product/stock/update`，支持商品详情、库存状态及风险提示。
- 订单对账：`/channels/ec/order/list/get`、`/channels/ec/order/get`；区分支付、退款、取消、售后以及广告归因订单。
- 售后经营：`/channels/ec/aftersale/getaftersalelist`，结合订单指标分析退款与售后；慎用写接口。
- 资金结算：`/channels/ec/funds/getbalance`、`/channels/ec/funds/getfundsflowlist`，**不可当作ADQ广告余额**。
- 营销与分销：`/channels/ec/coupon/create`、`/channels/ec/league/promotion/plan/list`，**联盟推广计划不是广告投放计划**。
- 直播关联：罗盘开播列表+广告平台转化数据，对账分析且必须标注延迟/归因差异。
- 精确权限和个人信息最小化：订单收货信息、手机号及结算信息不应进入AI默认上下文。

### 4.5 视频号微信豆加热

四份源文件尚未提供微信豆加热订单完整写接口。保留独立产品线和待接入状态；提供视频/直播选择、加热方案草稿、预算（微信豆单位）、订单查询适配位置、审批与人工官方入口。未确认可用写接口前不显示“创建成功/自动加热成功”。

## 5. 五大投放工作台重构

| 工作台 | 主界面 | 必补功能 | 平台差异 |
|---|---|---|---|
| 经营目标 | GMV、广告消耗、ROI目标与趋势 | 店铺/账户/场次分解、完成率、滚动预测、偏差复盘 | 支持不同业务计量和时间范围；不能混算归因GMV |
| 计划中心 | 专业列表+详情+操作抽屉 | 完整创建向导、定向选择、素材绑定、编辑版本、批量操作、草稿、审核 | 腾讯营销 adgroup/creative；巨量 project/promotion/DOU+；聚光 campaign/unit/creative；微信豆加热订单 |
| AI投放决策 | 异常队列+证据+建议+审批 | 诊断规则、分阶段监测、效果归因、手动/受控自动模式 | 支持的诊断/写入动作按账户能力返回；保留证据时间窗 |
| 预算调度 | 分配矩阵、余额、使用进度、风险 | 账户额度与实际余额区分，操作阈值，调拨审批，资金核验 | 腾讯钱包、巨量资金、小红书账户预算、微信小店结算四种不同概念 |
| 执行记录 | 任务列表+状态机+回读核验 | 原值/目标值/执行回执/异常重试/审计链路 | 不同平台的原生ID、回执格式、限流与同步频率不同 |

### 5.2 关键用户路径

- 腾讯：选微信小店→关联ADQ账户→选择商品/直播→目标与版位→定向→预算与出价→素材→审核→创建→回读结果。
- 巨量：选经营主体→巨量产品线→账户→项目/单元或DOU+订单→定向→预算→素材→审批→执行→核验。

## 6. 其余模块补齐

### 6.1 经营概况

继续仅将**今日广告消耗、支付GMV、投放ROI**设为三大核心KPI。下方增加可视化“消耗构成”“店铺支付成交”“广告归因差异”“平台异常”“待处理AI事项”。微信小店GMV为经营指标；广告渠道ROI的分子需按广告平台归因定义，不直接等同店铺支付GMV。

### 6.2 直播运营

微信小店罗盘可提供开播列表、店铺概况；巨量有直播间分析报表；腾讯相关车企视频号厂店数据为特定场景，不能当通用直播数据。直播间详情链接场次/商品/广告计划，明确不同平台数据口径及刷新间隔。

### 6.3 商品与货盘

将微信小店商品管理、库存、促销券、订单和售后形成“商品→曝光投放→成交→退款”的分析链；联盟达人带货单独功能区，避免与广告计划混同。

### 6.4 内容工厂

素材制作与管理统一；根据平台输出适配规格，绑定广告账户的已有素材ID、平台审核状态、投放计划及效果。腾讯/巨量提供素材新增和查询；小红书部分发布/创建素材路径未核验，不能默认为一键发布成功。

### 6.5 数据复盘

分“平台广告报表”“微信小店经营报表”“组合经营分析”；不同日期粒度、归因窗口、退款处理、跨渠道重复归因，应提供口径说明和不可比提醒。

## 7. 数据模型与API能力清单

统一对象：`BusinessEntity`、`Shop`、`Platform`、`ProductLine`、`AdvertisingAccount`、`Authorization`、`CapabilityGrant`、`Campaign`、`Project`、`AdGroup`、`PromotionOrder`、`AudienceDefinition`、`CreativeAsset`、`Order`、`Product`、`MetricsSnapshot`、`BudgetAllocation`、`Decision`、`Approval`、`ExecutionTask`。

每条能力需记录：`sourceFile`、`provider`、`productLine`、`operation`、`method`、`path`、`documentationStatus`、`scope`、`accountAuthorization`、`backendIntegration`、`runtimeAvailability`、`requestSchemaVerified`、`lastCheckedAt`、`limitations`。任何API只有目录依据时，默认不可执行。

数据隔离最少采用 `tenantId`、`businessEntityId`、`shopId`、`provider`、`productLine`、`accountId`、`nativeObjectId`，并绑定权限。前端接收后端能力清单，不在前端存放平台Secret；所有写操作通过后端审计网关、审批、幂等键、状态回读。

## 8. 实施优先级

- **P0 基础设施**：导入四份API图谱形成目录，梳理端点路径/权限/状态；平台与店铺的关系、产品线选择器、能力矩阵、数据源与口径、未接入空状态。
- **P1 核心投放**：腾讯ADQ完整投放向导（含动态定向）、计划详情、素材、审批和执行核验；优先使用已确认真实的查询/写入链路。
- **P2 微信电商闭环**：微信小店商品、库存、订单、罗盘与直播数据，与ADQ计划关联，实现真实经营效果复盘。
- **P3 巨量扩展**：选择一条账户真正具备权限的巨量产品线贯通创建→监控→诊断→调价→核验；DOU+独立订单向导；千川和本地推按实际授权逐条追加。
- **P4 聚光接入**：先实现真实账户和计划/单元/创意查询及报表、经授权的编辑；创造相关接口路径与请求参数确认后，再开放新创编。
- **P5 智能执行深化**：规则库、策略比较、受控自动化、跨平台预算建议、操作复盘。微信豆加热必须等到完整接口/授权确认后接入写操作。

## 9. 验收标准

1. 平台、产品线、账户、店铺可分别切换；不出现错账或跨账户残留数据。
2. 腾讯ADQ在权限允许的场景，可逐步完成目标、定向、出价、素材和预览；不可用字段准确提示。
3. 巨量营销、DOU+、本地推不互相套用错误表单；聚光缺失新建接口时只存草稿。
4. 微信小店经营GMV、广告归因GMV、退款、结算余额、广告账户余额不混用。
5. 任何平台修改都能回溯原值、批准主体、提交状态、回读结果和异常原因。
6. 所有表单可保存草稿、预览、撤回未执行申请；危险操作二次确认。
7. 有真实授权/写入能力才启用提交按钮；路径已核验不等于可调用。
8. 保持当前产品风格与其他已完成页面，前端开发范围内不修改后端。
