# 11 实施路线图

本册给出分期实施计划、每期范围、验收标准、前置条件与风险。节奏与前端 V9 规划的 P0-P5 对齐，原则是"先把身份和只读数据做真，再开放花钱的写链路，最后补智能与多端交付"。

2026-10-26用户明确的协作方式：前端一人、后端一人，双方结合coding agent，按任务粒度/依赖/验收门禁推进。M0–M5保留为功能范围，不换算人日或连续周数。问题见 [18册](18-前后端对齐评审与整改清单.md)，任务队列与验收见 [19册](19-细化排期与验收执行方案.md)。上一版按人日推导的周期撤销。

**平台对接分期（业务方已拍板）：一期只做腾讯系四个连接器（adq 腾讯营销广告、wxpromo 微信小店推广、wxshop 微信小店经营、beans 视频号微信豆），先在公司内部跑通运营、服务商、老板的真实使用并验证经营价值；抖音系（巨量营销/千川/DOU+/本地推/抖店）与小红书系（聚光/小红书电商）全部列入二期，在同一套执行内核与能力治理框架上复制扩展，一期不投入这两个体系的适配器开发。** 连接器框架、接口目录表、能力六阶段机制仍按八连接器设计（见 07 册），避免二期返工，但一期未对接平台的能力一律停留在 NOT_INTEGRATED，不产生任何"已支持"的错觉。

## 2. M0：工程底座与身份组织

目标：具备可部署、可登录、可鉴权的空骨架，前端能用真实会话替换 Mock 登录。

范围：

1. 仓库初始化：FastAPI 工程骨架、settings、日志、信封、异常映射、健康检查；ruff/mypy/pre-commit/pytest；Docker Compose（PG17/Redis/RabbitMQ/MinIO）；CI 流水线。
2. 数据库基线：Alembic、RLS 策略基件、公共模型与软删除/租户上下文中间件。
3. 身份域：邮箱密码 + 验证码登录（先接 SMTP 测试通道）、PostgreSQL 会话（Redis 缓存）、CSRF、登出、PATCH users/me；Identity 输出（权限推导 workspacePages）。
4. 组织域：租户、成员、角色、数据范围；预置五角色 OWNER/OPERATOR/AGENCY_OPERATOR/AUDITOR/PLATFORM_ADMIN；SQLAdmin 独立鉴权。
5. 前端联调：`/v1/auth/*` 真实联通；`.env.local` 切 api 模式跑通登录与未授权跳转。

验收：

- 未登录访问业务接口 401；无权限对象 403；跨范围构造请求拿不到数据（含 RLS 验证）。
- 验证码流程闭环（发送节流、错误次数、过期）；会话吊销即时生效。
- CI 全绿；干净库 `alembic upgrade head` 成功；管理后台可登录查用户。
- RabbitMQ 持久队列、发布确认、Outbox 补偿与 Worker 崩溃重投递在集成测试中验证通过（B0 工程验证项）。

## 3. M1：平台连接与腾讯系只读数据

目标：腾讯系真实平台数据进系统，概况、投放工作区、商品页有真数据；任何写操作仍未开放。抖音/小红书不在本期开发，连接器页面只展示"二期支持"的未接入状态。

范围：

1. 1818 条接口目录导入 endpoint_catalog（八个连接器目录全量导入，作为能力治理资料）；连接器框架（http、签名基类、registry、令牌加密与刷新、OAuth 回调）按八连接器端口设计，本期只实现 tencent/wxshop/beans 三个适配器骨架。
2. 腾讯 ADQ 只读：资产（账户/计划）、资金 funds 四口径、实时消耗、日报表；能力六阶段取证机制与 account_capabilities 输出。
3. 微信小店只读：商品/库存、罗盘概况、订单（最小化个人信息）、结算资金（MERCHANT_SETTLEMENT 独立口径）。
4. 微信豆只读摸底：视频号/商品可投对象的只读查询（若目录有合法只读路径并取证通过）；写操作不做，保持草稿/导出/人工入口。
5. 同步管道：platform 队列、sync_runs、原始载荷、metric_facts upsert、资金/资产/报表定时同步、新鲜度字段。
6. 接口：`GET /v1/frontend/snapshot`（source=API）、`GET /v1/delivery/workspace`（只读部分）、`/v1/connections/*`、`/v1/commerce/products`、`/v1/overview`。
7. connectors 状态输出（SUPPORTED/READ_ONLY/DEGRADED 等）；平台限流与熔断初版。

验收：

- 用真实试点账户拉到 ADQ 账户、计划、资金、报表与微信小店商品、罗盘、结算数据；页面显示来源时间与同步时间两个时间。
- 缺数据为空不为 0；店铺结算、广告钱包、微信豆分别展示；不同归因窗口数据不混算。
- 平台限流/断网时页面旧数据可读并标注异常，不出现 500；令牌刷新无人工干预。
- 能力矩阵与真实授权一致：未授权动作全部非 AUTHORIZED；抖音/小红书各账户能力明确为 NOT_INTEGRATED，前端不出现任何可写入口。

## 4. M2：中枢任务、风控与 ADQ 写闭环

目标：打通"对话指令 → 风控 → 审批 → 真实改预算/出价/暂停 → 回读核验"第一条真实写链路。这是全系统安全模型的验证里程碑。

范围：

1. 中枢：projects/conversations/messages、消息幂等；LLM 网关最小版（一个商用模型）+ 指令解析（三分类、消歧、单位提取）+ interpretations 留痕；规则解析降级。
2. command_jobs 全套接口（create/confirm/approvals/cancel）+ 12 态状态机 + 乐观锁 + 有效期过期（Beat）。
3. 风控：risk_policies 与四时点校验、冷却、额度汇总（含暂停计划）、能力时效校验。
4. 执行内核：execution_orders、审批服务（申请人/审批人分离、SERVER_POLICY 白名单）、幂等账、分布式锁、outbox、提交/回执/延迟回读/MATCHED 判定、UNKNOWN 对账任务、safe-retry。
5. 腾讯 ADQ 写适配器：预算、出价、ROI、暂停/恢复（小金额灰度账户先验，完成 EXECUTION_VERIFIED 取证）。
6. 通知：待审批邮件/站内；审计落库；执行记录时间线接口数据支撑。
7. 直播开关播：MANUAL_REQUIRED 交接流程（无推流控制）。

验收（对照 09 册安全清单）：

- 灰度账户完成至少各动作 5 次真实变更并全部 MATCHED；故意制造平台手动改动能产生 MISMATCH 告警。
- 断网/双击/同键重放不产生第二次写入；超时单据进入对账并能被定性。
- 规则版本变化后旧申请确认/批准均 409；服务商角色在无审批权时无法批准。
- AI 解析错误用例集（混合动作、无对象、单位歧义）全部安全落到澄清/拒绝，不产生错误任务。
- 全链路审计可回答"谁批的、何时执行、平台回执号、回读值"。

## 5. M3：投放工作台、腾讯创编向导与云端内容

目标：覆盖五个投放工作台与 V9 创编链路（仅腾讯系产品线）；内容从浏览器本地草稿升级为云端资产。

范围：

1. 投放 V8 契约：goals/breakdown、plan-changes preview+submit、budget-requests（层级/预占/事务校验）、decisions 规则引擎初版（ROI/PACING/CPA 等）、通用 approvals、policies（OBSERVE 默认）、verify/safe-retry、funds 四口径。
2. V9 配置工作台（腾讯系）：catalog/capabilities/options（腾讯标签、人群、版位真实选项）、audience-estimates、materials 上传、validations 一次性令牌、tasks 提交与查询、cancellations。
3. V9 integrations（腾讯系）：context（含 links 多对多）、queries 资源分页、previews/commands 走执行内核；字段六态全量支持。巨量/聚光产品线在目录中不可选，不做占位式向导。
4. 内容域：文档云端保存（revision）、素材资产与预签名上传、素材库列表/引用检查；NEXORA 对接（generation_jobs、回调或轮询、成片回收）；素材向 ADQ/微信推广上传与审核状态回写、account-links（两段链路）。
5. 直播：场次选择、分模块聚合接口、场次货盘云端草稿；开关播保持 MANUAL_REQUIRED。

验收：

- ADQ 完整创编向导（账户/目标/版位/定向/预算/素材/校验/提交/回读）在真实授权账户贯通；不适用字段准确置灰。
- 微信豆在无写证据时只能存草稿导出，系统任何状态不返回创建成功。
- 预算超额、上级额度不足、版本冲突分别得到正确拦截；AI 建议采纳必须进入审批。
- 素材上传-关联-平台素材 ID 链路可追溯；NEXORA 失败原因透传、无假进度。

## 6. M4：复盘报告、腾讯系补全与内部价值验证

目标：正式复盘与客户交付载体闭环；腾讯系四个连接器全部达到内部可用形态；在公司内部真实运营场景验证价值（提效、资金安全、老板看数、服务商交付），形成一期收口结论。本期不引入任何抖音/小红书开发。

范围：

1. analysis 全套：分析任务异步执行、不可变结果、周期校验（日/周/月覆盖度）、AI 章节叙述（引用证据）、草稿版本、发布固定版本、公开 token 阅读链接、HTML 导出。
2. overview 正式聚合：三 KPI、渠道/场次分布、待办与异常汇总（基于事实表/物化视图，范围为腾讯系数据）。
3. wxpromo（微信小店推广/视频号推广）：按 ADQ 同体系补全资产、报表与已取证写动作（预算/出价/暂停恢复走同一执行内核）；视频号小店资产作为投放对象的映射贯通。
4. beans（微信豆）：完成只读摸底结论；合法写接口若取得正式证明则按六阶段取证并接执行内核，否则固化为草稿/导出/官方入口跳转的人工方案，产品上明确标注。
5. 内部试点：选 1-2 个真实商家/账户由公司运营与服务商按日常流程使用（盯盘、改预算、内容 SOP、周报月报、老板审批），记录每类角色的使用数据与问题清单。

验收：

- 日报/周报/月报按数据覆盖规则正确放行或拒绝；发布链接免登录可读、可吊销、过期生效。
- 客户报告中每个结论可点回证据；缺成本/退款章节无利润结论；全部指标口径来自腾讯系真实数据。
- 腾讯系四连接器状态明确：adq 读写回读闭环、wxshop 只读闭环、wxpromo 按授权取证开通、beans 有明确"能/不能"的书面结论，无模糊地带。
- 内部试点产出量化价值小结（如改预算操作耗时、审批留痕完整率、报告出具耗时、UNKNOWN/差错单据数），作为是否启动二期与开放交付的决策依据。

## 7. M5：AI 增强、可观测与交付准备

目标：具备 SaaS 开放与私有化交付两种形态的上线条件；一期腾讯系能力整体收口。

范围：

1. AI 增强：诊断案例库（pgvector）、素材语义检索、指令上下文记忆；AI 费用看板与租户软限额；提示词版本与离线回归集。
2. 可观测：Prometheus 指标、告警规则、Sentry、系统状态页；对账与异常面板。
3. 安全验收：09 册全部清单（越权、重放、令牌泄露、会话、脱敏）。
4. 交付工程：TENANT_MODE single/multi 切换验证；私有化 compose 交付包（初始化、备份脚本、运维手册）；K8s Helm（若 SaaS 即刻需要）。
5. 自动化岗位：岗位配置（范围/规则/启停）、AUTOPILOT 低风险白名单试运行（仍保持强制人工审批三类动作）。

## 8. 二期：抖音系与小红书系连接器扩展

启动条件（建议同时满足）：一期内部试点价值结论通过评审；取得对应平台开发者主体与真实授权账户；一期执行内核、对账、能力治理在腾讯系上稳定运行。二期是在既有内核上复制平台，不改动资金安全模型。

| 批次 | 连接器 | 范围与纪律 |
|---|---|---|
| 二期 A（只读先行） | juguang 聚光、douyinshop 抖店、redshop 小红书电商 | 聚光先做 43 条已核验路径只读（计划/单元/创意/报表/笔记/账户预算）；抖店/红书店铺数据入商品与分析域，GMV 口径分开绝不相加 |
| 二期 B（一条写产品线贯通） | ocean_marketing 巨量营销 或 dou_plus | 按实际授权二选一：营销项目/单元走标准配置向导；DOU+ 走独立订单向导，禁止与项目/单元模型混用；写链路完整复用执行内核与六阶段取证 |
| 二期 C（逐接口扩写） | qianchuan 千川、local_push 本地推、juguang 创编 | 账户授权与接口版本确认前 operations 为空、能力 NOT_INTEGRATED；创编类 50 条未核验路径不开放写入 |

每个新连接器的上线验收标准与 M1/M2 相同：真实账户只读新鲜度、小金额灰度各动作 5 次 MATCHED、MISMATCH 演练、断网重放不重复写入。二期排期不在本册承诺，按一期价值验证结论与商务节奏另行排期。

## 9. 前置条件（需要业务方/陆文龙侧提供）

开发不被这些条件完全阻塞（可先用沙箱与桩），但对应里程碑验收必须具备。

一期（腾讯系）：

1. 腾讯广告开发者主体、应用类型、app_id/secret、OAuth 回调白名单、沙箱或灰度账户（M1 前）。
2. ADQ 真实可跑的 GET 接口清单与实测失败码（M1 中持续）。
3. 一个可用于小金额写入验证的 ADQ 真实账户（M2 前，最关键）。
4. 主体/视频号小店/直播间/广告账户的真实 ID 关联关系与一个微信小店商家授权（M1-M2）。
5. 微信豆是否存在合法写接口的正式渠道结论（M4 前）；没有则固化人工方案。
6. LLM 供应商合同/密钥与预算（M2 前）；NEXORA 对接文档、鉴权方式与回调能力（M3 前）。
7. 生产服务器、域名、ICP 备案、HTTPS 证书、正式 SMTP/企业微信 webhook（M2 联调环境前）。

二期（抖音/小红书，一期不阻塞）：

8. 巨量开发者主体与各产品线账户权限清单、沙箱账户；千川/本地推接口版本资料（二期启动前）。
9. 小红书聚光开发者资质、50 条未核验路径的实际方法/参数、小红书电商授权（二期启动前）。

## 10. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 腾讯授权/scope 拿不到，写链路无法验证 | M2 延期 | 尽早启动平台资质申请；先用只读与沙箱，写验证排在资质后；不降低取证标准上线 |
| 一期平台收窄后业务方临时要求插单抖音/小红书 | 一期失焦、内部价值无法验证 | 本文档为分期依据，新平台需求统一进二期评审；连接器框架已预留，插单不改变内核但占用人力，须显式替换一期范围 |
| 平台字段/版本变化频繁 | 创编向导返工 | 能力驱动 + JSONB 原始载荷，字段不硬编码；变更先改能力数据不改核心 |
| AI 解析误判导致错误操作 | 资金风险 | 结构校验、候选消歧、金额确认、人审四道闸；模型不碰风控和执行 |
| 结果未知/对账复杂度被低估 | 状态长期挂起、账实不符 | M2 就建对账机制与异常面板；宁可挂起不可重放 |
| 同源平台限流策略不清 | 同步拖垮或被封 | 配额可配、错峰、熔断；同步只读先行观察真实限额 |
| 服务商多租户关系复杂引发越权 | 客户数据泄露 | RLS + 数据范围 + 审计三重；M0 即做越权测试 |
| 团队对 FastAPI/异步不熟悉 | 质量风险 | 编码规范与分层约束先行；核心模块双人评审；先写状态机/风控单测 |
| 私有化环境无法使用公网 LLM | 交付受阻 | LLM 网关 OpenAI 兼容设计，内网 vLLM 平替，M5 提前演练 |
| 一期内部试点价值不达预期 | 二期与开放决策缺乏依据 | M4 以真实角色日常使用做试点并留量化记录；不达标先修正产品与内核，不急于铺平台 |

### 10.1 性能与恢复验收基线（内部起步，不是对外 SLA）

先用构造数据量出真实基线（建议 10 个租户、100 个账户、1000 个计划、1 万条业务任务及代表性素材），再决定副本规模：

| 指标 | 初始目标 | 测量边界 |
|---|---|---|
| 常规列表/详情 | P95 ≤ 500ms | 固定数据集，鉴权后，命中/未命中缓存分别统计 |
| 创建/审批 | P95 ≤ 1 秒 | 完成数据库事务即返回，不等平台执行与生成 |
| 状态变化到两端可见 | P95 ≤ 3 秒 | 事件投影 + SSE + 客户端重读 |
| 基线负载 | 20 个并发运营、50 RPS、50 条 SSE 连接 | 构造验收场景；LLM 生成单独压测并记录首 token 与费用 |
| 故障恢复 | API/Worker 重启后任务可解释恢复，不重复投放或扣费 | 单机允许短暂停机，记录在途 UNKNOWN 与积压消化时间 |

M2/M5 必须通过的故障演练用例：同键异载荷 409、两个审批人竞争、取消与 Worker 领取竞争、并发增额、策略批准后变更策略、外部改计划旧值变化、平台返回前 Worker 崩溃、平台成功但落库失败、消息确认前后崩溃、平台最终一致延迟、UNKNOWN 长期不可核实、授权撤销、跨租户越权、RabbitMQ/数据库故障、SSE 断线重连、数据库恢复后的在途核对、生成已扣费但响应丢失与重复回调。M0 还需完成 RabbitMQ publisher confirm、acks_late 与 Worker 丢失重投递的真实集成验证，不停留在配置假设。

## 11. 人员与协作建议

- 固定前端一人、后端一人，双方结合coding agent；任务卡明确agent输入/允许范围/验收命令，负责人承担本端复核、契约和联调。核心资金/隔离证据由两位负责人共同复核，不默认新增开发或额外评审人。
- 与前端协作按契约走：每个里程碑开始前冻结该批接口 schema，FastAPI OpenAPI 导出对接；联调期接口变更即时更新契约文档，不口头同步。
- 与业务/陆文龙的例行事项：腾讯平台资质与实测进展每周同步一次；每次真实写入演练有记录归档（同时作为能力证据）。
- 分支与提交遵循仓库 git-workflow：本地分支开发、完成检查后合main；文档入库可追踪，不代表架构/上线审批已通过，门禁按证据另签字。

## 12. 最小可用闭环（MVP 定义）

如果资源受限需要最短路径见到业务价值，最小闭环为：

真实登录 → 授权一个微信小店 + 一个 ADQ 账户 → 概况与计划看到真数据 → 手机或 PC 发一条"把某计划日预算调到 X" → 风控提示 → 老板审批 → 真实执行 → 回读 MATCHED → 执行记录留痕。

这个闭环全部在腾讯系内完成，跑通即证明架构最难的身份、租户、能力、风控、执行、回读、审计全部成立；二期的抖音与小红书都是在同一套内核上复制扩展。

MVP 只开放已取证的日预算动作，另须具备 UNKNOWN 可见性、只查不写、备份恢复、人工异常处置和基础告警。其余出价/ROI/暂停恢复按 G2 逐动作验收后放行；不能把预算动作通过记作所有平台动作通过。对应R00–R07、F00–F06/F12核心与A01–A25适用项见19册。
