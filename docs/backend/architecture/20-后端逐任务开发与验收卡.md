# 20 后端逐任务开发与验收卡

版本：V1.1（已授权逐项执行），2026-10-26（Asia/Shanghai）

状态：**用户已要求自检、提交Git，并依清单逐项开发和验收。** 开发按本地分支→验证→合并main→推送main执行；各卡实际进度与证据见[执行台账](../evidence/task-status.json)。授权开发不代替双端复核、真实账号权限、平台写操作和供应商费用许可。

基线：本地 `c2257a0`；仓库尚无 `backend/` 实现。原101个后端任务细化为145个实现/验收叶任务，另有4个R00规格卡，共149张卡；另列7个门禁，门禁不是代码任务。前端14张F卡和42项A验收沿用 [19册](19-细化排期与验收执行方案.md)，没有重复计入后端卡数。

## 1. 怎么审阅、怎么开始

1. 先审阅本节的约定与第2节的依赖调整，再检查第3节默认队列；重点审看MVP以前的资金/恢复卡和第12节外部输入。
2. 初始卡均未执行；实际状态以执行台账为准。编号、计划文件存在、静态检查通过都不代表实现或真实验收已通过。
3. 用户确认后，从 `R00-01` 开始，一位后端负责人结合Coding Agent逐卡实现；一位前端负责人按19册F卡并行准备和联调。不默认增加开发人员，也不以人日/工时或人数折算日历。
4. 本卡依赖通过本卡所需层级的验收才可领取；正式门禁必须包含适用前端和真实环境证据。若只是前端未接线，后端实现可记“后端已验证、待联调”，不能记整链DONE。
5. 缺外部账户/密钥只阻塞相应实调；允许先完成离线实现，状态记“已实现、待真实验收”。不得把离线通过等同P类任务或门禁通过。继续领取其余真正READY卡。
6. 一个原任务拆成多个子卡时，全部适用子卡完成才关闭原任务；不再单独下发原父卡、也不重复计完成。当前149卡及101父任务映射见第11节。

### 1.1 每张卡共同继承的交付要求

- 负责人均为唯一BE负责人；Agent负责卡内实现、自测、回归与证据整理。列出的F卡代表FE协作点，不授权本轮改前端代码。
- 原实现模块、测试目录、迁移/文档边界均以卡中范围为限。共享文件先指定一位维护人；同一迁移头和公共模块禁止并发改写。
- 通用输入：02/03工程约定、04/13数据模型、05/14 HTTP契约、06/12/15资金与恢复、07连接器、08 AI、09安全、10运维、16内容SOP；结合当前前端源码冻结，而非只照旧样例抄写。
- 每卡交付：范围内代码、必要迁移/配置示例、含正反例的验证、脱敏证据索引、缺陷/阻塞及影响说明。无持久化变更的任务可不新增迁移，但说明“不适用”。
- 每卡下方有三条必须核对的DoD；不得仅用“完成接口”“测试通过”关卡。A编号只指该案例中本卡负责的子场景，不代表整个A案例或其他模块同时PASS。
- 证据拟归档 `docs/backend/evidence/tasks/<任务ID>/`：版本、环境、实际命令、输入/预期/实际、请求/业务/尝试ID及复核人。真实凭据和未脱敏截图放受控证据库，仓库仅保留索引。
- 卡的验证文件是**拟新增交付物，不是当前已存在或已运行的测试**。通用ruff/mypy、空库迁移、契约及受影响回归依风险执行；不为每个小改动无条件重跑全部无关测试。
- Git按最新用户授权与项目规范处理：只提交本任务相关文件，开发分支不推远程，合并main后推送；不得覆盖伙伴更新。

### 1.2 验证层级与命令口径

D类规格卡使用当前已有工具和双方评审即可完成，不依赖后端工程。U/I/C/P命令由M0-01建立入口，在 `backend/` 目录执行；实际执行记录归入任务证据。测试路径为拟定位，可合并同域验证文件，不强制创建149个独立测试文件；下发时登记实际用例/命令并保留本卡正反例，禁止用空壳测试关卡。

| 类型 | 验收内容 | 计划验证入口 | 不足以关卡的情形 |
|---|---|---|---|
| D | 规格/Schema/约束/状态表/依赖图静态核对与两端决议 | 现有PowerShell/Node等工具；证据为差异/决定及静态检查 | 把纸面核对称为真实数据库或平台验收 |
| U | L1规则/转换/边界/架构单元验证 | `uv run pytest tests/unit/plan/test_<任务ID规范化>.py -q` | 空测试、只断言常量等于实现 |
| I | L2真实PG/Redis/MQ/对象存储或进程故障 | `uv run pytest tests/integration/plan/test_<任务ID规范化>.py -q` | 只Mock数据库/队列却声称集成通过 |
| C | HTTP契约及相应客户端校验，L3另由F卡留证 | `uv run pytest tests/contract/plan/test_<任务ID规范化>.py -q` | JSON能解析但字段/枚举/范围错误 |
| P | L4真实账户/供应商/运营证据，且含适用L1/L2/L3 | `uv run pytest -m live tests/live/plan/test_<任务ID规范化>.py -q`；业务观察另留记录 | 缺key/账户被跳过、夹具或HTTP200冒充真实通过 |

任务ID规范化为小写并把连字符替换为下划线，例如M2-10b→`test_m2_10b.py`。M0-01注册live标记并默认排除；P类涉及真实写/付费时必须先核对批准账户、动作、金额与单次调用许可，未获许可不运行。纯调查/运营观察任务的live入口用于校验证据引用，不自动执行付费或广告动作。
