# G0 门禁复核清单

生成日期：2026-10-29（Asia/Shanghai）；用途：供 BE/FE 负责人对 G0 范围内 26 张卡逐项具名复核，解除阻塞 E08，放行 G0。

门禁定义（19 册 §6）：**G0 = 身份/空工作区 + 隔离/可靠消息底座**，签字角色 BE+FE，依据必须是真实数据库与队列集成，单元 Mock 不算。当前台账中 G0 状态为 `BLOCKED`，`blockedBy = E08`，唯一剩余条件是双端具名联合复核——技术证据已齐，不接受 Agent 代签。

## 1. 复核方式

1. 每张卡读 `tasks/<卡ID>/README.md` 与其引用的 `verification.json`。
2. 按 `review-template.md` 在该 README 追加复核记录（任务ID、基线提交、复核人姓名/角色/日期/确认来源、逐条 DoD 结论、证据或缺陷 ID、结论、批准范围）。
3. 通过后把台账 `tasks.<卡ID>.review.backend`（或 `.frontend`）改为 `PASS`，并登记 `review.records.<角色> = {name, date, baseline, source}`；不涉及 FE 的卡填 `NOT_APPLICABLE` 并附 `review.frontendReason`。
4. 全部适用卡双端通过后，G0 才可从 `BLOCKED` 改为 `PASSED`；不要求先把 85 张 WAITING\_REVIEW 全部签完，只签本清单 26 张。
5. 签字基线用签字当日的 `main` 完整提交号；表中提交号是该卡交付时的技术基线，用于回溯核对。
