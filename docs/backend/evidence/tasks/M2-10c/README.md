## 实现与三条DoD

1. 0034增加每申请唯一budget_job_finalizations与逐额度桶budget_adjustments。match只消费已有verified_action_facts ID和明确job版本，不接客户端MATCHED布尔或金额。证明必须与当前执行单/attempt的原WRITE、独立READ、已应用PLATFORM受理回执以及当前fence/owner一致；公开状态须VERIFYING。核对规范CNY旧/新值与E2 observed_value，短事务共同写MATCHED/SUCCEEDED、执行EFFECTIVE、HELD→SETTLED、B/R和变化账，最后才将本目标守卫IDLE；租约过期本身不妨碍只读证据定性，但旧fence不得结算。相同E2重复/并发调用返回首结果，不能用另一种证明覆盖终结账。
2. B以最近完整budget_observations内该账户/计划的组件值为起点，并叠加同一观察基线下该组件最近一次结算结果。完整同步已经含新值时budget_delta=0、只扣R；否则仅补尚未记入B的差额。组件出现第三值或比独立回读更晚的冲突完整观察时拒绝结算，等待对账，不用较早E2覆盖新真值。所有适用桶按顺序行锁，R必须等于全部HELD合计；正增额的当前预占必须HELD且等于冻结delta。增额结算不会把外部超限事实丢掉；仅在OVER_LIMIT且结算后B+R已回限时清除此冻结，其他原因保持。
3. release只接受两种已实现的充分依据：真实状态内核产生的未领取/未发送REJECT/CANCEL/EXPIRE当前版本事件，且不存在执行单；或同原尝试、已应用、当前fence的PLATFORM明确拒绝E1回执。仅改FAILED标签、超时、未知、受理待回读或隔离旧fence均不能释放。取消/过期可由申请人办理，驳回释放可复用实际审批人REJECT权限的同Session；终结账保持申请人私有。R只扣实际HELD一次，RELEASED不可再变SETTLED。原始拒绝/E2回执不直接按状态字符串操作额度。其他对账E1证明类型在M2-18实现后接入，当前不接受自报CONFIRMED_NOT_EXECUTED。

减额/不变值没有负数或零HELD；只有同样严格的独立E2匹配后才按新组件差额调B，R维持其他真实预占。资金、job/事件、执行/守卫、变化账与审计复用同Session；外部HTTP均在取得原始证明阶段完成，不放进结算事务。审计失败整体回滚。运行身份无直接UPDATE/DELETE资金或终结账权限。

## 验证与输入边界

22项专项覆盖普通增额、全量同步已计入新值避免重复B、四并发仅一终结账、减额不创建预占、明确拒绝释放一次、超时/200未确认/受理不能释放、实际内核取消/驳回/过期与释放同事务、匹配和释放审计失败完整回滚、旧fence/版本/新完整观察/外部第三值拦截、SETTLED不能换证明释放、FAILED无E1仍保留HELD、预占合计损坏或明细缺失不得伪造RELEASED。过期用例明确由维护身份提前初始时间，实际内核过期谓词真实执行，不冒充M2-07扫描器。FAILED故障夹具曾只改状态列而触发ck_job_complete，已同时维护文档状态，最终复跑以verification.json为准。

本卡真实执行PG、归档、完整预算同步、风险、预占、状态内核、行锁、并发与审计。供应商仍是显式MockTransport；E2先由既有独立维护校验导入器验证受理/回读、完整上下文、规范请求/观测值及来源时钟，再由运行角色消费。运行时独立回读生产者归M2-17，本卡不宣称真实ADQ执行生效，也不以维护输入代替平台验收。完整命令、数量和开发库迁移见verification.json。
