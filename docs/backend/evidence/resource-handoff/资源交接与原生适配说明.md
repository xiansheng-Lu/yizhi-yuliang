## 复用与适配

- ADQ复用独立项目的固定GET `/oauth/token` 换码/刷新协议；新授权必须返回与本资源native_id一致的authorizer_info.account_id，不能把应用scope视为所有账户授权。
- 微信小店复用商家自研 POST `/cgi-bin/stable_token`，普通续期 force_refresh=false；不套ADQ授权页，也不为自研模式虚构外部回调。
- 驭量复用原有真实会话、connection.manage、CSRF、一次性state、AES-GCM TokenCipher、RLS与追加审计。state绑定原管理员会话、应用与回调。
- 续期按授权使用PG事务级advisory lock，竞争者拒绝并行刷新；刷新成功写回轮换凭据，失败或取消持久化REFRESH_FAILED，REVOKED不允许刷新。
- 新迁移0039仅增加受限的access.renew_provider_token函数。它复核当前actor、管理员会话、版本及应用，普通角色仍不能直接更新status/expires_at/scopes。
- 首批业务只读经既有GovernedPlatformClient→RecordedPlatformClient→固定出站白名单，凭据由服务器按租户、店铺、内部账户、原生ID、应用和授权核对。写端口一律拒绝。
- 回调query在ASGI入口移入SecretStr并清空访问日志scope，失败路由同样处理；反向代理仍须按路径记录回调，禁记原始query。

## 运行配置及HTTP入口

Settings新增唯一可选项 `YULIANG_PLATFORM_RESOURCES_FILE`，指向私有resources.local.json。
未配置时保持原行为；已配置但所有资源禁用时不读取密钥、不出网，也不生成ACTIVE连接。
启用需要真实identity接口、业务租户/店铺/原生对象映射、权限依据、固定回调及唯一刷新者交接；配置缺项拒绝启用。
原生业务读取还需相应产品线的内部account_id及真实能力绑定。小店不得借用ADQ账户映射。

| 方法/路径 | 作用 |
|---|---|
| GET /v1/connections/applications | 当前管理员可见的本租户应用，不返回Secret引用或令牌 |
| POST /v1/connections/applications/{applicationId}/authorize | ADQ返回授权URL；小店自研通过后台凭据建立授权，均要求CSRF |
| GET /v1/connections/oauth/{applicationId}/callback | ADQ回调，无需浏览器Cookie，依赖一次性state恢复并复核原会话 |
| POST /v1/connections/{authorizationId}/renew-token | 当前管理员会话下串行续期，仅返回状态与有效期 |
| POST /v1/connections/{authorizationId}/refresh | 现有F03重授入口，创建新授权，不复活旧能力证据 |

ADQ必须登记 `/v1/connections/oauth/{applicationId}/callback` 的完整HTTPS地址，不能把独立测试项目旧回调path直接认作驭量已部署路由。
微信小店自研使用内部应用绑定摘要，不要求外部OAuth回调；scope仅取有后台证据的资源配置，稳定token本身不返回scope。
keyring_file为私有JSON文件，键为正整数版本字符串、值为base64的32字节密钥；state_secret_file为独立至少32字符密钥。
这两类服务端密钥在实际启用时由后端生成并安全保管，不在聊天或仓库提交。本次未生成或启用真实密钥。

当前实现提供受控续期入口，没有部署新的无会话常驻刷新任务。不得将接口交付当成后台调度已上线。
驭量接管前必须停止旧服务/直连刷新者，核对单一所有者后才允许token_owner_transferred=true；本次该字段保持false。
