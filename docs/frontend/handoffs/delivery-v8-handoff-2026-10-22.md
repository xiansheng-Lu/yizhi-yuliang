# 易致·驭量 V8.0 投放管理前端交付记录

日期：2026-10-22，Asia/Shanghai。

本次完成前端重构和待接入能力的产品交互。没有开发后端，没有真实广告平台写入/资金操作，也不将页面渲染或Mock审批当作真实投放完成。

## 1. 实际修改的页面

保留原路由与权限ID，投放管理仍为五个稳定入口：

| 路由 | 工作台 | 实际改造 |
|---|---|---|
| /app/plans | 计划中心 | 平台化列表、搜索/筛选/排序、自定义列、分页、多选、批量预览、创建向导、行内调整及独立详情；移除正式渲染路径中的常驻申请大表单 |
| /app/goals | 经营目标 | 独立经营目标，不再把企业风控规则当成经营目标；核心进度、四类趋势、连续日差额、周期/状态筛选、制定/拆解/调整及历史 |
| /app/budgets | 预算调度 | CNY/微信豆分别展示经营额度、进度、账户/计划分配矩阵、实际资金、预算建议、安全边界及执行冲突 |
| /app/decisions | AI投放决策 | 决策卡片队列、证据区、样本/延迟/可信度、建议处置、预算边界关联、规则和三种权限模式 |
| /app/executions | 执行记录 | 任务列表、完整10种状态、来源/类型/状态筛选、详情、配置前后对比、回执脱敏、时间线、核验与受控重试入口 |

只对统一导航/前端layout/入口/API传输层做必要挂接。官网、认证、经营概况、商品、内容工厂和复盘模块的业务结构未重写。直播工作台仅在入口外增加上下文桥和双向ID链接，不重做直播大屏。

## 2. 新增的二级工作区

- 计划/订单详情：配置、效果趋势、关联对象、AI诊断、预算历史、执行记录。
- ADQ创建四步向导；独立微信豆加热四步方案向导与人工方案导出。
- 配置调整对话框：前后对比→服务端风险预检/旧command_job草稿→确认送审→执行记录。
- 批量选择和逐项风险校验对话框；不伪造批量平台写入能力。
- 经营目标制定、对象拆解、调整预览；目标详情与变更记录。
- 内部预算新分配、调整申请、可用额度核对及审批预览；账户资金/AI优化/风险控制分区。
- 决策详情、同意/驳回/暂缓/修订、规则编辑与模式预览。
- 执行任务详情、确认/审批/取消、独立预算及新版任务审批资源、核验请求、安全重试确认及实际效果复盘入口。
- 各页按真实所选对象发起AI分析，不再使用无上下文的通用聊天按钮。

## 3. 平台自适应机制

`src/lib/delivery.ts` 定义平台目录、对象判别联合、能力/权限状态、资金单位、刷新配置、URL上下文和指标口径。

`DeliveryProvider` 读取现有Workspace身份及快照，建立平台/店铺/账户/日期范围。后端能力声明与身份权限共同门禁，缺失声明不放行。`supportedObjects/supportedMetrics/supportedFilters/supportedColumns`及schema约束驱动当前账户可用区域。

`DeliverySessionProvider` 在现有layout内共享身份隔离的筛选偏好、未提交草稿和未知结果账户锁；不持久保存令牌或伪造正式状态。切换前支持保留会话草稿、放弃、取消；关闭浏览器或完整重载后草稿不保留。

查询由范围键、AbortController及LatestDeliveryRead代次隔离。旧账户的延迟成功/失败均不可覆盖新账户。新范围不读取旧范围缓存；失败仅保留同范围历史记录，撤权清空业务缓存。切换事务期间阻断写入。

## 4. ADQ与微信豆差异

ADQ使用Campaign、计划/广告组/广告层级、CNY分、预算与受支持的出价配置；保留原生计划ID。创建字段从账户schema获取真实推广目标、内容类型和金额约束。

微信豆使用PromotionOrder、视频/直播内容、加热目标、豆额度、时间、进度、播放/互动。没有ADQ出价/启停通用字段。没有正式订单API时显示待接入；具有真实关联账户后可配置和导出明确标识的人工方案，不创建假订单。

全平台提供综合管理和分单位展示；修改、审批或创建前要求具体平台和账户，不提供跨平台通用广告写入表单。微信小店保持交易店铺身份。

## 5. 已复用的接口

保留既有 `ApiClient` cookie鉴权、响应封装、取消/超时和错误处理，以及snapshot、setScope、createJob、confirmJob、reviewJob、cancelJob等调用。通过受限的deliveryRequest复用传输，不替换现有服务为Mock。

**“仓库中已有调用”不等于“本次已验证真实后端”。** 当前环境是演示模式，无正式ADQ或微信豆联调证据。原risk-policies服务不删除，也不再冒充新经营目标接口。

## 6. 仍需后端支持的能力

聚合投放工作区与账户级能力声明、原生ID映射、计划版本/审核/趋势、微信豆订单、经营目标和拆解、预算分配/真实余额/账户级边界、AI证据与规则、策略审批、结果核验及安全重试。

每项已定义TypeScript、Service入口、加载/错误/权限状态和接口契约。没有后端授权时提交按钮不可用，允许配置、预览或人工引导，不显示“平台成功”。

## 7. 平台授权限制

真实账户授权、操作scope、页面/用户权限、能力版本、有效同步、后端风控必须全部满足。自动化默认观察；受控自动须后端明确授权。新增消耗、预算增加和重要计划关闭默认人工审批。

超时、网络中断或无效写入响应按账户锁住本次会话重复写入，仍可分析/核验。明确结果前不自动重放；重试必须由后端明确标记safeRetry并使用原幂等键。

## 8. Mock清理与隔离

投放正式适配路径仅保留ADQ和微信豆渠道；wxpromo、千川、聚光及其他混合连接器记录不会展示为这两类平台。保留全项目原mock-data及其他模块正常功能，不做跨模块删除。

沿用显著演示标识，ADQ演示记录只读，不调用正式投放写入口；微信豆订单不从人民币计划推造；目标、资金、AI证据和预测缺失时显示未知。没有定时变更Mock数值模拟经营增长。

## 11. 尚未完成及原因

1. 真实平台读写、资金同步、AI诊断及后台执行核验没有完成联调，因为仓库没有上述新后端接口和可验证平台授权；本任务限定仅做前端。
2. 批量平台写入没有实现伪成功：目前支持多选、批量预览和逐项服务器校验。后端需确认批量幂等、部分失败及审批模型。
3. 页面分页对已返回完整集合生效；大规模生产数据的后端分页、摘要总数和过滤参数仍需协议扩展。
4. 本地未提交草稿为内存会话，不是跨设备或持久化业务草稿；如需持久化，应由后端提供草稿资源及权限。
5. 新经营目标、预算方案和AI队列在无真实对象时显示完整空态与交互入口，图表没有制造曲线、余额、目标达成、预测或优化收益。
6. 商品/素材和既有经营复盘已传递ID，但其更深入定位功能属于原模块协作范围。
